# SuperDL engineering conventions (shared by people and AI agents)

GPU compute rental platform. Architecture in `docs/architecture.md`, module contracts and invariants in `docs/reference/` (index `docs/README.md`), UI/UX spec in `docs/ui-ux-spec.md`, decision log in `docs/decisions.md`, onboarding and workflow in `CONTRIBUTING.md`.

## Repository layout

```
apps/api       FastAPI modular monolith (uv; one image with two entry points: serve / worker)
apps/web       user console (Vite + React 19 + antd 6, light theme)
apps/admin     admin console (same stack, dark NOC style)
packages/api-client  generated by orval from openapi.json (never edit src/generated by hand)
packages/ui    theme tokens, status badge mappings, money / duration formatting, shared copy
deploy/        ansible control-plane install / cluster helmfile and runbooks / app K8s manifests and local compose / node-join tests / instance images
e2e/           Playwright browser smoke
docs/          architecture, module reference, UI/UX spec, copy style guide, decision log
scripts/       release script and repository-level gate scripts
```

## Common commands

Backend commands run inside `apps/api`; start the local dependencies from the repository root first (`docker compose -f deploy/app/compose.yaml up -d`). API and worker each get their own terminal. `seed_dev.py` is dev/test only; `bootstrap_admin.py` creates the first production administrator and prints the password once.
Backend pytest needs Docker (testcontainers PG18); every parallel worker starts its own container, so run single-file tests without `-n`.

```bash
uv sync
uv run alembic upgrade head
uv run python scripts/seed_dev.py
uv run python scripts/bootstrap_admin.py
uv run uvicorn app.main:app --reload
uv run python -m app.workers.main
uv run ruff format . && uv run ruff check --fix .
uv run pyright
uv run lint-imports
uv run pytest -n 8
uv run pytest tests/test_x.py
uv run alembic revision --autogenerate -m "..."
uv run alembic check
uv run python -m app.export_openapi
uv run python scripts/export_error_messages.py
```

The following run from the repository root. The browser smoke needs the API and worker running; set `SUPERDL_ADMIN_E2E=1` to enable the admin cases.

```bash
pnpm install
pnpm dev / build / format / lint / typecheck / test / i18n
pnpm api-client
pnpm --filter @superdl/e2e test:e2e

bash -n apps/api/app/modules/nodes/assets/node-join.sh && shellcheck apps/api/app/modules/nodes/assets/node-join.sh
bats deploy/node-join/tests
python3 scripts/check-docs-links.py
python3 scripts/check-page-skeleton.py
bash scripts/check-cjk.sh --scope repo
```

## Hard rules (violations are sent back)

1. **Money**: `Decimal` / `numeric` end to end, never float. Unit prices 4 decimals, ledger entries 2 decimals, `ROUND_HALF_EVEN`, everything through `app/core/money.py`; the deployment currency comes from `platform_currency()`, user-visible amounts are formatted with `money_label()`.
2. **Time**: DB columns are always `timestamptz`, code always aware UTC (`app/core/timeutil.now_utc()`); billing days and periods follow the deployment's `billing_timezone` through the `billing_*` helpers.
3. **DB change + K8s change go through the outbox**: the business write and `outbox_tasks` share one transaction; the request path never calls K8s directly (the single exception is the read-only instance log read, see `docs/reference/orchestrator.md`). Worker-side patrols may talk to K8s directly.
4. **Wallet updates use `SELECT ... FOR UPDATE`** and write `balance_ledger` (with balance_after) in the same transaction.
5. **The billing basis is `instance_events`** (running ↔ non-running edges); Prometheus metrics are for display and reconciliation only.
6. **Module boundaries**: `app/modules/*` may import only each other's public surface: `service.py`, `schemas.py`, plus `account/deps.py` and `account/deletion.py`; `orchestrator` additionally exposes `queries.py` (read-only), `transitions.py` (system-side transitions), `statemachine.py` (state constants) and `ports.py` (port pool), none of which depend on billing, and they are the only path for billing settlement and patrols into orchestration. `billing` must not import `orchestrator/service.py` (it depends on `billing/service.py`; the reverse is a cycle). Function-level imports are allowed only in `wiring.py` / process entry points / on-demand third-party SDK loading (ruff PLC0415 enforces); module cycles are broken by moving code, never by local imports. import-linter enforces this.
7. **API contract**: OpenAPI-first. After changing a route or schema, re-export openapi.json and run `pnpm api-client`; the frontends never hand-write fetch, they use the generated fetchers (hooks are built in `apps/web/src/api/*.ts` / `apps/admin/src/api.ts`).
8. **Unified error body** `{code, message, message_key, params, detail, request_id}` (`app/core/errors.py` AppError); create-type POSTs support `Idempotency-Key`.
9. **Every write goes through the audit middleware**; admin and user APIs are physically separate (JWT audience `user` / `admin`).
10. **State machine transitions** only through the transition functions of `orchestrator/service.py` (writing instance_events in the same transaction); never UPDATE status directly.
11. **Frontend**: wrap antd 6 native components yourself, no pro-components; all server state goes through TanStack Query; copy and status mappings are centralised in `packages/ui`.
12. **Copy**: the error catalog's single source of truth is the English `core/messages.py`; `uv run python scripts/export_error_messages.py` regenerates `packages/ui/locales/en-US/errors.json`, `packages/ui/locales/zh-CN/errors.json` is maintained by hand and key parity is tested. UI copy lives in the two apps' locales JSON; zh-CN and en-US are committed together, style in `docs/copy-style-guide.md`. Server-rendered copy (notifications, admin alerts, ledger remarks, payment subjects) goes through `core/servercopy.py` and follows the deployment's default locale (from `compliance_profile`), never the request language; CSV exports take an explicit `lang` with the same default.
13. **Tests**: every case can answer "what is broken when it fails". Mandatory cases: money and rounding, overdraft, settlement idempotency, hour / day / month and timezone boundaries, state machine transitions, idempotency keys and outbox replay, auth and role boundaries. No coverage threshold. The end-to-end source of truth is `apps/api/tests/test_e2e_lifecycle.py`, the browser smoke `e2e/tests/`.
14. **Secrets and credentials never enter git**: injected only through environment variables or the platform configuration centre; deploy templates always say `CHANGE_ME` (`deploy/app/secrets.example.yaml`). The prod-required set is the `_validate_prod` list in `docs/reference/security.md`. Licensing: `LICENSE` (Apache-2.0) and `NOTICE` at the repository root are authoritative; no per-file license headers.
15. **Migrations and releases**: stop-the-world releases (stop → `alembic upgrade head` → start), no compatibility window, no rollback (downgrade always raises); destructive DDL is allowed and the commit message states the data impact; `uv run alembic check` must pass; `/readyz` accepts only DB == code head.
16. **Docs travel with the code in the same commit**: changing an endpoint, table, role, default, patrol interval, command or procedure updates the matching `docs/reference` page, runbook or README in the same commit; new decisions go to `docs/decisions.md`; docs and comments state current facts only, never review numbers, change history or dates. References are checked by `python3 scripts/check-docs-links.py`.
17. **English everywhere**: source, comments, docstrings, log / hint / error source strings, docs, commit messages and operator output are English. Chinese is allowed only in `locales/zh-CN/**` and the generated `apps/*/src/types/resources.d.ts`, the zh-CN error catalog, the legal presets (`apps/api/tests/legal_preset.py` and seeded migrations), `e2e/tests/**` (Playwright is pinned to zh-CN accessible names) and single lines marked `cjk-ok` where the Chinese literal is the point (a zh fixture, a regulatory name). The gate is `bash scripts/check-cjk.sh --scope repo`; `REPO_CJK_ALLOW` in the script is empty and stays empty.
18. **Region-neutral defaults, opt-in compliance**: defaults serve any region (`compliance_profile=none`, `platform_currency=USD`, `billing_timezone=UTC`, `captcha_provider=turnstile`, `node_install_mirror=official`). Mainland-China integrations (Aliyun SMS / captcha / KYC, Alipay, WeChat Pay, the `cn` installer mirror, the PRC phone requirement) are opt-in, switched by `compliance_profile=cn`. Deployment identity (`SUPERDL_COMPLIANCE_PROFILE`, `SUPERDL_PLATFORM_CURRENCY`, `SUPERDL_BILLING_TIMEZONE`, `SUPERDL_WEB_BASE_URL`) is env-only, required in prod and locked by the `billing_identity` row. Security features are `*_enabled` switches plus provider enums; the only sanctioned stand-ins are `sms_provider=mock`, `email_provider=mock`, `payment_mock=true` and `k8s_backend=fake`, all refused in prod. No mock captcha or KYC providers.

## Do-not-edit list

- `packages/api-client/src/generated/**` (orval output, regenerated only through `pnpm api-client`)
- `apps/api/alembic/versions/*`: append only; the DDL / data statements and the revision chain of released migrations never change. Zero-behaviour changes (comment and docstring wrapping, splitting helpers in the original order) are allowed with proof that behaviour is unchanged: statement-by-statement comparison + `alembic upgrade head` on an empty database + `alembic check`

## Workflow and commit conventions

- `main` is protected: changes are committed on short-lived branches and merged through PRs; a PR needs CI fully green and at least one reviewer, squash merge; never force-push `main`.
- Commit message prefixes `feat:` / `fix:` / `chore:` / `docs:` / `test:` / `ci:` / `refactor:`, one sentence saying what changed.
- One PR does one thing and can be reverted alone. Purely mechanical changes get their own PR; contract regeneration (openapi.json / orval output / error copy / i18n types) goes into the same commit as the change that caused it.
- Run the local gates matching the change; never push red. CI (`.github/workflows/ci.yml`) is the merge gate and the full gate list:
  - Backend: ruff format/check → pyright → import-linter → pytest; model / migration changes add `alembic check`, route / schema changes add "openapi.json has no diff"
    - ruff complexity caps (cyclomatic 12 / branches 14 / statements 60, `apps/api/pyproject.toml`): split the function, never add noqa; pyright uses only the root `pyrightconfig.json` (standard + errors on unnecessary ignores / unnecessary comparisons / private access); white-box tests that reach into module internals declare `# pyright: reportPrivateUsage=false` at the top of the file
  - Frontend: prettier --check → eslint → tsc → vitest; copy / locale changes add `pnpm i18n`, build configuration changes add build
  - Scripts: bash -n → shellcheck → bats
  - Docs: `python3 scripts/check-docs-links.py` and the repository-wide CJK gate `bash scripts/check-cjk.sh --scope repo` (rule 17); Markdown outside `deploy/` and `apps/api/` also passes `pnpm format:check`; changes touching only docs or comments run just these two
  - User-visible main paths: Playwright smoke
  - CI only: pip-audit / pnpm audit, gitleaks, kubeconform (`deploy/app/k8s`), the RealOrchestrator smoke on kind
