# ansible: initial control-plane install and host hardening

`site.yml` only installs the rke2/k3s server on server nodes (including the two follow-up servers in HA; on k3s it also installs the cluster state backup); `harden.yml` hardens sshd / firewall / accounts / sysctl on every host (servers + agents). GPU nodes do not join through ansible but through the one-shot command generated by the admin console "Add node" (`../node-join/README.md`; the script itself is `apps/api/app/modules/nodes/assets/node-join.sh`).

## OS baseline

- **Debian family** (Ubuntu Server 22.04 / 24.04 LTS is the validated baseline, Debian 12 is the same family), x86_64 or aarch64; the playbooks use apt throughout.
- Target machines: root or sudo (`become: true`), python3, reachable over ssh, with public egress: the installers are downloaded from the official sources `get.rke2.io` / `get.k3s.io` by default (`k8s_install_mirror: official`); mainland-China data centres can switch to `rancher-mirror.rancher.cn` with `-e k8s_install_mirror=cn`; any other value fails the playbook assertion.

## Inventory groups

See `inventory.ini.example`: `[servers]` (control plane; list every server for multi-server setups) and `[agents]` (GPU nodes, used by `harden.yml` only).

## site.yml

Run from this directory after replacing the addresses in `inventory.ini` with the target servers. Pick one of the two playbook commands: RKE2 (full) by default, `cluster_distro=k3s` for light.
Control-plane parameters go into `group_vars/servers.yml`, which is not committed; keep sensitive values off the command line:

- RKE2 snapshots: `etcd_snapshot_bucket`, `etcd_s3_region`, `etcd_s3_endpoint`, `etcd_s3_access_key`, `etcd_s3_secret_key`.
- `agent_token`: one independent random credential shared by every server (at least 32 characters), entered under admin "Platform configuration · Cluster access"; never use the server node-token.
- HA: `api_vip` and `server_ips` (odd count ≥3); optional `server_hostnames` are added to the certificate SAN as well.
- Private Harbor CA: put the full PEM into `harbor_ca_pem`, leave it empty for publicly trusted certificates; also configure the Harbor's `configs` → hostname → `tls.ca_file` in `../cluster/rke2/registries.yaml`, pointing at `/etc/rancher/<distro>/harbor-ca.crt` on the target machine. Pull credentials are managed as a Secret per `../cluster/README.md` "Image registry".

```bash
cp inventory.ini.example inventory.ini
ansible-playbook -i inventory.ini site.yml
ansible-playbook -i inventory.ini site.yml -e cluster_distro=k3s
ansible-playbook -i inventory.ini site.yml -e k8s_install_mirror=cn   # mainland-China mirror
```

### Behaviour

- Order: kubelet drop-in (`../cluster/rke2/kubelet-superdl.conf`, podPidsLimit) + audit-policy.yaml + registries.yaml (+ harbor-ca.crt when non-empty) → server config (rendered from the repository template, written 0600 only when no placeholder remains) → install the rke2/k3s server (the installer is fetched by `get_url` with `checksum: sha256:…` into the root-private directory `/root/.cache/superdl/`, `force: true` overwrites an old file, then runs; idempotent) → enable+start → wait for the kube-apiserver `/readyz` → apply the placement label `node-restriction.kubernetes.io/superdl-infra=true` to the control-plane nodes (`--overwrite`, idempotent) → on k3s install the cluster state backup. `restart-server` runs only when the config changed.
- The installer sha256 values are `rke2_installer_sha256_official` / `_cn` and `k3s_installer_sha256_official` / `_cn` in `site.yml`, chosen by `k8s_install_mirror`; they equal the pins built into `node-join.sh` (cross-checked by bats); change both places when upstream or the mirror updates an installer.
- The placement label must be applied here with admin credentials, not through the distribution's `node-label`; nodes are selected by the `node-role.kubernetes.io/control-plane` role, not by hostname. Definition in `../cluster/README.md` "Platform component placement label".
- Tasks that carry credentials are all `no_log: true` (server config rendering, tls-san append, write); errors carry no content, debug on the target machine in `/etc/rancher/<distro>/config.yaml`. Values are injected through `| to_json`, never by hand-built quoting.
- HA parameters come in pairs: `api_vip` and `server_ips` must be given together with an odd count ≥3, otherwise the playbook assertion fails; a single-server cluster leaves `api_vip` empty.
- k3s cluster state backup: `../cluster/k3s/state-backup.sh` is installed as `/usr/local/sbin/superdl-k3s-state-backup` (0700 root) with the cron `/etc/cron.d/superdl-k3s-state-backup` every 6 hours (`23 */6 * * *`); dependencies `sqlite3 gnupg rsync`; mirror host, passphrase and ssh key reuse `/etc/superdl/pg/backup.env`, `backup-passphrase`, `backup-ssh-key` (see `../pg/README.md`), and the cron fails while those three files are missing on the server. `cluster-init: true` in `k3s/server-config.yaml` migrates an existing SQLite single server into embedded etcd at the restart triggered by the config change: run `superdl-k3s-state-backup` once by hand before executing. Restore is in `../cluster/README.md` "Cluster state backup and restore".
- After the install continue with path A/B in `../cluster/README.md` (platform access → `preflight.sh` → `apply.sh`).
- The driver version is delivered by the platform configuration `node_driver_version` (admin · Platform configuration) and installed by node-join.sh at that version; this directory does not hold it.

## harden.yml

Runs after `site.yml` (servers) and node-join (GPU nodes) against every host in `[servers]` + `[agents]`, repeatable:

```bash
ansible-playbook -i inventory.ini harden.yml -e '{"cluster_cidrs": ["10.0.0.0/24"]}'
```

What it does:

- sshd drop-in `/etc/ssh/sshd_config.d/10-superdl.conf`: `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `ChallengeResponseAuthentication no`, `PermitEmptyPasswords no`, `PermitRootLogin prohibit-password`, `UsePAM yes`, `MaxAuthTries 3`, `LoginGraceTime 20`, `X11Forwarding no`; `AllowUsers` when `ssh_allow_users` is non-empty. TCP forwarding stays (ops port-forward / tunnels). The `10-` prefix sorts it before Ubuntu cloud-init's `50-cloud-init.conf` (`PasswordAuthentication yes`). After writing it runs `sshd -t`; on failure the drop-in is withdrawn and the play aborts; only on success is ssh reloaded.
- **Lock-out guard**: before turning password login off it asserts that the target has at least one usable public key (with a non-empty `ssh_allow_users` only those users count, otherwise root and users with uid ≥ 1000 with `authorized_keys`); without one it fails without changing anything. If `ssh_allow_users` does not include the connecting user, your next connection after the run is refused.
- `remove_users` (default empty, **opt-in**): `state: absent`, home kept. Set `remove_users: ["test"]` once you have confirmed the `test` account has no process / cron / sudoers dependency; including the connecting user fails the assertion.
- nftables (`firewall_enabled: true`, can be turned off per host in host_vars): `/etc/nftables.conf` declares only `table inet superdl`, `input` defaults to drop: allows lo, established/related, ICMP/ICMPv6, DHCP client, SSH (`ssh_allow_cidrs`, default `0.0.0.0/0`, **narrow it to the office / bastion / VPN ranges**), sources in `pod_cidr` / `service_cidr`, cluster ports from `cluster_cidrs` sources (`fw_cluster_tcp_ports` / `fw_cluster_udp_ports`, see the comment table at the top of the playbook), NodePorts 30000-32767 from any source, and additionally 80/443 on `[servers]`. The template is pre-checked with `nft -c -f` before writing and applied with `nft -f` only on success; no `flush ruleset`, and the `ExecStop` of `nftables.service` is changed to delete only this table (the distribution default `flush ruleset` would wipe the iptables-nft rules of Docker / Cilium / kubelet). `ufw` must stay inactive. `ssh_port` only changes the firewall allow, not the sshd port.
- sysctl `/etc/sysctl.d/60-superdl-harden.conf`: `kernel.dmesg_restrict=1`, `fs.protected_regular=2`, `fs.protected_fifos=2`, `fs.protected_hardlinks=1`, `fs.protected_symlinks=1`; `rp_filter` is left alone (Cilium manages it).
- No fail2ban: password login is off and SSH sources are narrowed by `ssh_allow_cidrs`.

Variables go into `group_vars/all.yml` (not committed): `cluster_cidrs` (required), `ssh_allow_cidrs`, `ssh_allow_users`, `remove_users`, `firewall_enabled`, `pod_cidr` / `service_cidr` (k3s defaults `10.42.0.0/16` / `10.43.0.0/16`; rke2 uses the same defaults), and the four port lists.

Check after the run: confirm from a second terminal that ssh still works; `nft list table inet superdl`; from another node `kubectl get nodes` all Ready, the tenant NodePort SSH connects, the three Envoy domains are reachable.
