# Decision log

Cross-module decisions, and decisions that keep getting questioned. Each entry states only **what was decided** and **what constraint it puts on later changes** — no argument, no history; intra-module trade-offs are recorded in the module documents.

## Engineering process

- **`main` is protected; changes land through short-lived branches and PRs.** A PR needs a fully green CI and at least one review, and is squash-merged; no direct pushes, no force-pushes. Constraint: one PR does one thing, and the unit of revert is one merge commit.
- **CI is the merge gate; local gates are the pre-push self-check.** Run the local gates that match the change and do not push red; dependency audits, gitleaks, kubeconform and the kind smoke test run only in CI.
- **Frontend static analysis = strictTypeChecked + Prettier.** ESLint uses typescript-eslint's strictTypeChecked + stylisticTypeChecked (projectService type-aware); there is one `.prettierrc` (printWidth 120 / LF) and `pnpm format:check` is part of the CI frontend gate. Constraint: redundant guards (`?.` / `??` on values the types already prove non-null) are caught by `no-unnecessary-condition`; rules are narrowed only per-option with a stated reason, never switched off wholesale.
- **No coverage threshold.** Every test must answer "if this fails, what broke?".
- **There is one command list**: "常用命令" in CLAUDE.md; the README only has the quick start. <!-- cjk-ok -->
- **Downtime releases: no compatibility window, no rollback.** The order is always "`alembic upgrade head` first, then swap the code"; `/readyz` accepts only DB == code head and pulls the instance out of rotation on behind / ahead / unknown. Destructive DDL is allowed with the data impact spelled out in the commit message; downgrade always raises; alembic history is a linear chain from the single baseline `20260901_1620c05976ce`, guarded by `alembic check`.
- **Apache-2.0, copyright "The SuperDL Authors".** `LICENSE` is the canonical text, `NOTICE` carries the copyright line and third-party notices, and the license is declared in every `package.json` and in `pyproject.toml`. Constraints: no per-file license headers (generated files would lose them anyway); no CODEOWNERS for now; the git history is published as-is.
- **Release notes are not maintained by hand.** `gh release create --generate-notes`; there is no CHANGELOG.
- **orval generates fetchers and model types only, not TanStack Query hooks.** `packages/api-client` uses `client: "fetch"`; both consoles wrap the fetchers in useQuery / useMutation under `apps/web/src/api/*.ts` and `apps/admin/src/api.ts`. Constraint: keep `client` at `"fetch"`, never add a `query` block.
- **Query keys have one source of truth per console, conditional queries use `skipToken`.** web: `apps/web/src/api/keys.ts`; admin: `adminKeys` in `apps/admin/src/api.ts`; invalidation and definition reference the same factory, no hand-written key literals in components. Constraints: a nullable input (no fetch while the id is null) is always `queryFn: x === null ? skipToken : () => fetch(x)`, never an `as` cast plus `enabled`; the error type is pinned globally to `ApiError` through `Register.defaultError` (web `api/register.d.ts`), not per hook.
- **Disabled placeholder items have an admission rule.** Only capabilities that are scheduled and settled by the current design stay as disabled placeholders labelled "coming soon". Constraint: any change updates the placeholder list in `docs/ui-ux-spec.md` and `docs/reference/web.md` in the same commit.

## Interface

- **The user console has no separate overview page; the home page is the instance list.** KPIs live in the top bar balance and the billing page; announcements / balance warnings / arrears collapse into one `AttentionBar` on top of the instance list, and onboarding lives in the true empty state. Constraint: no "dashboard"-style summary pages; every new site-wide notice joins the `AttentionBar`, no extra banners.
- **Console top bars are neutral; the brand gradient appears only on public pages and the login page.** Constraint: inverted CTAs on the gradient use `brandInverseButtonStyle`; `brand.topBarBg` never appears inside the consoles.
- **Primary navigation is grouped and holds only resource and purchasing pages.** web: resources / purchases and billing / support; admin: overview / resources / business / governance. Notifications and account settings are reached through the top-bar bell and user menu. Constraint: the grouping sources of truth are `consoleNav.tsx` and `lib/menu.ts`; sidebar, drawer and command palette may only read them.
- **Persistent hints need a reason to exist: time-bound and actionable.** Policy explanations are not persistent `Alert`s; they go to tooltips, rule dialogs or card footnotes. Constraint: at most one banner per page, items aggregated; compliance statements appear only in the public footer and the marketplace footer.
- **Confirmation strength is a shared component set in both consoles; `Popconfirm` is banned.** L1 / L2 `useConfirm`, L3 `TypeConfirmModal`, admin audited actions `ReasonAction`; dangerous confirm buttons are always red. Constraint: no hand-rolled `modal.confirm`; confirmation copy = a question title naming the target + a consequence body.
- **Admin density is "compact", user density is "comfortable", fixed in tokens.** Admin tables 13 px / `cellPaddingBlock 8`, wide tables with fixed columns + sticky header + full-width page; the user console keeps antd's default density. Constraint: the consoles never borrow each other's density; the wide-table criterion is `scroll.x ≥ 1000`.
- **Polling periods have one source (`POLL`), and polled pages show freshness.** Constraint: no bare millisecond literals for new polls; page headers use `PageHeader.freshness` for "updated at / auto refresh / paused".
- **URL parameters have no legacy aliases; whitelist-and-drop is the whole strategy.** `validateSearch` accepts only the current whitelist and strips invalid values back to defaults. Constraint: renaming a URL parameter or enum value is a direct change, no normalisation code.
- **"Disabled with a reason" is written one way: `GatedButton`.** Constraint: a non-empty `reason` means `aria-disabled` + focusable + click intercepted + Tooltip; a `Tooltip` wrapping a `disabled` Button is caught by ESLint; native hard-disable is only for in-flight submissions; items inside `ReasonAction` / `ChipRow` / `RowMoreMenu` use it too.
- **Pages own their `PageContainer`, identically in both consoles.** The shell only provides top bar / sidebar / `<main>`; each route decides its own width and header. Constraint: a new page starts with `PageContainer` (the page-skeleton script guards it), filters use `FilterBar`, entity headers use `EntityHeader`.
- **Shared components are drawn where "generic means shared".** `FilterBar / RowMoreMenu / AttentionBar / ChipRow / useLeaveGuard` live in `packages/ui`; `CheckoutBar / ConsentGate / OnboardingSteps` (web) and `ReasonAction / BulkBar / ListCapNote / AuditTable` (admin) stay in their console. Constraint: before writing a generic component in one console check whether the other already has it — promote, do not copy; the `useLeaveGuard` core has no router dependency, each console wraps it to inject `useBlocker`.
- **JS reads semantic colours only through `useThemeColors()`.** Constraint: the three `themeColors` sets (web-light / web-dark / admin) are the only JS colour source, no direct `import { colorPrimary }`; `useThemeMode` is used only in `__root.tsx` and the theme toggle; chart themes come from `useChartTheme()`; `HexTag` picks black / white text by background luminance.
- **"Pick one" controls are divided by role; the billing-mode picker stays a ChipRow.** `Segmented` for view switching, `ChipRow` for filters and light options, `OptionTile` for mutually exclusive form choices, an in-table radio to pick a row. Constraint: `Button + aria-pressed` and `Radio.Group optionType="button"` are banned; the billing mode is a `ChipRow` on both the marketplace and the create page (the `role=group` named "计费方式" is pinned by two e2e cases) — move it, do not change the control. <!-- cjk-ok -->
- **Restorative admin actions get no second confirmation.** Uncordoning a node, unfreezing a tenant, listing a SKU only ask for a reason; destructive ones (cordon, freeze, delist, reclaim, force-stop) keep reason + second confirmation. Constraint: confirmation strength never inverts — restoring must not be harder than destroying.
- **"See everything at a glance" is the instance list's status count bar in the user console and the overview's pending bar in the admin console.** Constraint: counts come from loaded data or existing list endpoints — an exact summary endpoint is a roadmap item; every overview KPI deep-links to a pre-filtered list.
- **The public landing's first screen is a price board, not a poster.** Every number is real data; no generic marketing modules; the public layer follows the theme; prices / models / commands use a self-hosted monospace font (in web's public directory, CSP `font-src 'self'` already allows it, the index.html inline script is untouched). Constraint: any number on the landing page comes from `/skus` or `gpuSpecs.ts`.
- **Account settings are tabbed; finance reconciliation does not embed the audit log.** Four settings tabs (`?tab=`); the audit log lives only under `/audit`.
- **Design tokens are enforced by ESLint.** Colour hex literals, `Space size={number}`, `Drawer` `width` and literal `size` are errors under `apps/**` and `packages/ui/src/**` (the token definitions `tokens.ts` / `color.ts` / `status.ts` and the contrast regression test are exempt); `turbo.json` lists `eslint.config.mjs` in `globalDependencies`. Constraint: a new semantic colour enters `tokens.ts` first; theme-dependent colours in JS go through `useThemeColors()`.
- **Console page skeletons are locked by a script gate.** `python3 scripts/check-page-skeleton.py` scans `apps/web/src/routes/_console*.tsx` and `apps/admin/src/routes/_app/*.tsx`; every page must own a `PageContainer`; part of the CI frontend job. The public layer is out of scope.
- **e2e selectors prefer role + name; `data-testid` is only for elements without a stable role or text.** The list lives in packages/ui's testIds module (`mfa-secret` / `endpoint-url`); table rows use antd `data-row-key`; confirm buttons are located through `getByRole("dialog")`, not `.ant-modal-confirm-btns`.

## Billing and funds

- **Zero balance means reclamation, and the criterion is always the available balance (balance − frozen).** Unfreeze when `available > 0`, stop when `effective <= 0`. Constraint: the six arrears-patrol criteria (coarse filter / re-read under lock / low-balance payload / stopped→frozen / frozen→unfreeze / data-disk arrears chain) never fall back to the raw balance. Locked by `apps/api/tests/test_billing_flow.py::test_zero_balance_stops_then_freezes_then_reclaims` and `apps/api/tests/test_patrol_arrears_frozen.py`.
- **Billing trusts the event stream only; metrics are for reconciliation.** Settlement runs unchanged with Prometheus down. See `docs/architecture.md` §4 and `docs/reference/billing.md`.
- **No in-channel refunds.** Approval does not touch the wallet; finance records the payout and only then is the wallet debited; approval and payout are different people. See `docs/reference/payment.md`.
- **Two gates against double cashing invoices and refunds**: a refund request is refused for an invoiced period (locking that period's active invoice rows); issuing an invoice recomputes the amount under a row lock and rejects a mismatch. See `docs/reference/payment.md`, `apps/api/tests/test_invoices.py`.
- **Payout and its audit row share a transaction.** A failed audit write rolls the payout back (`write_audit_sync`).
- **Settlement gaps are recorded, never self-healed.** Catch-up truncation / dead letters / lost watermarks land in `settlement_gaps` and keep alerting until replayed or resolved by hand. See `docs/reference/billing.md`.
- **Subscriptions are a separate prepaid order, not zero-amount hourly bills.** `bills_hourly` structure, idempotency keys, watermarks and gaps stay untouched. Constraint: the only skip point is `apps/api/app/modules/orchestrator/queries.py::billing_candidates`; the purchase mode is excluded at four companion filters (burn rate / stop criterion / freeze and unfreeze / tail bill), each listed in `docs/reference/billing.md` and locked by a test.
- **Periods are fixed hour counts, not calendar months.** day=24 / week=168 / month=720 / year=8760; expiry and pricing use the same number. Constraint: `PERIOD_HOURS` is a constant, not a policy parameter.
- **Prepayments are not refunded; early release only cancels the subscription; the exception is an instance that never ran.** Entering `releasing` turns active subscriptions `cancelled` without a refund row; real refunds go through manual `refund_requests`. Constraint: cancellation hangs on the state-transition listener and covers user release, arrears reclamation, expiry reclamation and admin force-reclaim; historical `expired` rows are untouched. A first `creating` that times out (Pod never ready) is not "early release": the reconciler refunds the prepayment and cancels the subscription in the same transaction.
- **Expiry never falls back to on-demand.** Expiry stops → freezes → reclaims after 72 hours (sharing `freeze_grace_hours` with arrears). Companions: a warning 3 days ahead, optional auto-renew (default off), renewing inside the frozen window unfreezes.
- **Renewals are repriced from the order-time snapshot.** The base is `subscriptions.unit_price`, not the current SKU price (renewing with a different period takes that period's discount). Start time is `max(old expiry, now)`. Constraint: a renewal **inserts a new row** linked by `renewed_from_id`, never accumulates on the old one.
- **An unexpired subscription instance holds inventory even while stopped.** Soft admission's `_reserved_slots` counts "stopped / frozen but still covered" instances on the same SKU as occupied. **Reserved at the platform layer only, never physically**, and the create page and renewal entry must say so. Same SKU only.
- **On-demand converts to a subscription in place, each side settling its own account.** `POST /api/v1/instances/{uuid}/subscribe` runs in one transaction **settle, then flip**: `settle_on_demand_up_to` closes the on-demand account at the pre-conversion price up to the current clock hour, then the subscription row is inserted, the period pre-debited, `market` flipped and `price_hourly` refreshed. Constraints: the order is fixed; **idempotent replay is decided before every guard**; **settlement lag above 48 hours refuses the conversion (409)**. No reverse path. `subscribe_instance` is the only path that sets `market` to subscription. See `docs/reference/billing.md`, `docs/reference/orchestrator.md`.
- **Preempted spot instances are settled normally, nothing is waived; the settlement engine is untouched.** Moving to `stopping` issues the tail bill through the existing `edge_listener`. Constraint: `billing_candidates` still skips only `market != 'subscription'`; the discount lands only in `instances.price_hourly`, computed in one place, `price_for` in `apps/api/app/core/pricing.py`. See `docs/reference/billing.md`.
- **Spot → on-demand treats the crossing hour as "one hour, one price"; lagging hours are settled first at the spot price.** `bills_hourly` has one row and one `unit_price` per hour, taken from the instance price at settlement time: first `settle_on_demand_up_to` (same as the subscription conversion) closes the unsettled clock hours after the watermark at the spot price, then `settlement.reprice_current_hour` rewrites the current hour's `unit_price` under the wallet row lock, recomputes `amount`, debits the difference and marks `detail.repriced`. Constraint: only extra debits, never refunds (`spot_discount_pct` caps at 90); this must be stated in the conversion confirmation dialog. See `docs/reference/billing.md`.
- **WeChat Pay signature verification uses the WeChat Pay public-key mode only, never platform certificates.** `wechat_public_key` and `wechat_public_key_id` are required channel settings; either missing is a `PAYMENT_CHANNEL_ERROR`; a callback whose `Wechatpay-Serial` differs from the public-key id is rejected before reaching the SDK. See `docs/reference/payment.md`.
- **Reversal markers on a channel notification are written, never cleared.** `channel_reversed_at` means "received", `channel_reversal_resolved_at` + `channel_reversal_action` mean "handled"; a release does not clear the marker and a replay of the same notification does not freeze twice. Callback freshness window ±15 minutes. Constraints: a release is a single-operator action but every one alerts; every write to the signing roots (payment / crypto configuration groups) alerts (`PaymentConfigWritten`), no two-person rule.
- **One currency and one billing timezone per deployment, locked in `billing_identity`.** `SUPERDL_PLATFORM_CURRENCY` (default USD, 0- or 2-decimal currencies only) and `SUPERDL_BILLING_TIMEZONE` (IANA, default UTC) are env-only; the first boot writes them to the single-row table and every later boot must match. Constraints: re-keying is allowed only while no ledger / order / bill row exists or with `SUPERDL_BILLING_IDENTITY_REKEY=true`, and never converts stored amounts or day/period keys; `orders.currency` is set at creation. See `docs/reference/platform-config.md`.
- **Settlement bootstrap does not record a gap.** No watermark and no billable object before the window = first deployment, only the watermark is created; history present → `watermark_missing` is recorded. See `docs/reference/billing.md`.

## Security

- **Security trade-offs are recorded in one place.** Tokens in localStorage, fixed-window rate limits, no user-side 2FA, residual two-person gaps and the rest are listed under "已接受取舍" in `docs/reference/security.md`; do not reopen them as separate items. <!-- cjk-ok -->
- **All admin roles require TOTP.** Switch `admin_mfa_enabled` (default on), only all-on / all-off; prod cannot switch it off online, only through the deployment layer; switching off raises a config-center warning and records the audit reason; the four-layer login rate-limit buckets stay. See `docs/reference/admin.md`.
- **Log PII / credentials are masked globally.** `apps/api/app/core/logging.py` masks by key name (phone / email / handle / id_number / token / secret / password / code).
- **Account-level login lockout.** A 15-minute window plus a daily-window step lockout per account, on top of the per-IP buckets. Constraint: **the admin daily account bucket counts only after a failure and is not part of the pre-bcrypt admission check** (the user side still is). See `docs/reference/admin.md`.
- **Tenant SSH ingress excludes only the Pod CIDR, not the whole private range.** Port 22's `from` is `0.0.0.0/0` except `tenant_pod_cidr` (default `10.42.0.0/16`). Constraint: changing the CNI CIDR means changing `tenant_pod_cidr` too; an empty value is only a temporary troubleshooting fallback. See `docs/reference/security.md`.
- **Email is the primary login handle; phone is an optional E.164 handle.** `users.email` (unique when set, verified at sign-up) and `users.phone` (E.164, unique when set) are both nullable; sign-in / reset / deletion take one `handle`, sign-up needs an email and binds a phone only with its own SMS code (required and region-restricted by the compliance profile). One `verification_codes` table serves both channels (`account/verification.py`); rate-limit buckets key on `core/handles.ratelimit_key`. Constraints: bare national numbers are never accepted; deletion NULLs both handles instead of writing a placeholder; accounts without an email keep phone sign-in and are prompted to add one. See `docs/reference/account.md`.
- **Regional compliance is a deployment profile, not a set of online switches.** `SUPERDL_COMPLIANCE_PROFILE` (`none` | `cn`, `app/core/compliance.py`) selects which regional rules apply; `none` is the international default. Constraints: the profile is env-only and required in prod; `SettingSpec.prod_forbidden_profiles` scopes a prod rule to profiles (CAPTCHA / real-name / real-name-before-recharge are `cn`-only gates; admin MFA and non-mock SMS apply everywhere); `/site-config` publishes the profile's user-facing flags so the consoles never hard-code a region. See `docs/reference/platform-config.md`.
- **English everywhere, enforced by a repo-scope gate.** `scripts/check-cjk.sh --scope repo` (CI `docs` job) fails on Chinese text in any tracked source or document except UI locales, generated files, frozen migrations, legal presets, zh-CN e2e selectors and lines marked `cjk-ok`; `REPO_CJK_ALLOW` lists the paths still awaiting translation and only ever shrinks. Constraints: new files are written in English; a feature PR touching an untranslated document writes its delta in English; translation PRs change wording, not facts.
- **Hardware-specific facts live in one runbook, and the defaults are hardware-neutral.** `deploy/cluster/runbooks/hardware-notes.md` collects what differs per platform (Grace GB10 / GB200: no passthrough, unified memory, no GRUB argument on aarch64; x86 IOMMU argument by CPU vendor; Debian-family baseline; official installer hosts). Constraints: code and values reference the runbook instead of restating a platform quirk; no value in `deploy/cluster/values` is tuned to a single machine model.
- **GPU capability tables have one source: the backend.** `core/gpu_models` decides MIG and passthrough support; `NodeOut.supports_mig` / `supports_passthrough` carry the verdict to the admin console, whose pool-switch modal no longer keeps its own family sets. Constraint: `packages/ui/src/gpuSpecs.ts` stays a display-only spec sheet and must not grow capability semantics.
- **The k3s / rke2 installer source defaults to the official hosts; the mainland-China mirror is an opt-in.** `node_install_mirror=official` (get.k3s.io / get.rke2.io) is the default everywhere; `cn` selects rancher-mirror.rancher.cn. Constraints: node-join accepts only these two values and fails closed on anything else (no silent fallback to a mirror); both origins keep their own sha256 pins and a mismatch prints expected/actual plus the refresh command; a mainland deployment must set `cn` explicitly when upgrading.
- **`node-join.sh` speaks English, ASCII only.** Operator output, progress messages (which the admin console shows verbatim under pending nodes) and comments in the node-join script are English so the script serves any operator; the bats suite asserts the English strings. Constraint: no `≥`-style symbols in output (`>=`), because the text lands in logs, JSON progress payloads and terminals of unknown locale.
- **Invoice tax IDs follow the compliance profile.** The request schema only requires a 2–32 character `tax_id` for company titles; `invoices.TAX_ID_RULES` maps `ComplianceProfile.invoice_tax_id_rule` to a validator (`cn_uscc` → PRC unified social credit code), so the international default accepts VAT-style identifiers as typed and the consoles show generic copy unless the site reports `compliance_profile=cn`. Constraint: the refund-blocked-by-invoice message says \"voided or credited\", not the PRC-specific red-letter term. See `docs/reference/payment.md`.
- **Recharge bounds and presets are policies, not contract constants.** `recharge_min` / `recharge_max` / `recharge_presets` live in the policy group (admin-editable, `/policies` publishes them); the request schema only rejects absurd values (>1e8, ≤0). Constraint: presets must lie within the bounds and min ≤ max, enforced on write. See `docs/reference/limits.md`.
- **Stripe Checkout is the international card channel; refunds stay off-channel.** Orders map to hosted Checkout Sessions keyed by the order number (client reference + PaymentIntent metadata), webhooks are verified with the endpoint signing secret, and card refunds / disputes only freeze the credited balance for the finance refund flow (payout `offline`). Constraints: the `stripe` SDK is imported lazily inside the channel; no network call happens at construction; a `stripe_refund` payout channel is a documented follow-up. See `docs/reference/payment.md`.
- **Payment channels are a registry, not a set of if/else branches.** `payment_channels/spec.py::CHANNELS` declares each channel's switch, credential fingerprint, factory, webhook path and ack body, settlement currencies, refund payout counterpart and console presentation (`qr` | `redirect`); the factory, webhook router, `/site-config`, recharge gating and refund payout options derive from it. Constraints: a channel name fits `orders.channel` (16); `create_payment` returns `PaymentInit(url, channel_ref)` and never a bare QR string; a channel that cannot settle the platform currency is refused at order time and flagged as a config error. See `docs/reference/payment.md`.
- **The billing calendar is the deployment's IANA zone, not a fixed offset.** `SUPERDL_BILLING_TIMEZONE` drives `timeutil.billing_zone()`; daily disk bills, the fund reconciliation, invoice periods and admin day filters are civil days/months in that zone, stepped with `billing_day_shift` so DST days keep one window per local date; daily cron jobs fire at local wall-clock times. Constraints: no `BILLING_TZ_OFFSET_MINUTES`-style constants; client display aggregation keeps an explicit `tz_offset_minutes` that defaults to the zone's current offset. See `docs/reference/billing.md`.
- **Console money formatting is `Intl` over the deployment currency.** `CurrencyProvider` (`packages/ui/src/hooks/useCurrency.tsx`) carries the ISO code from `/site-config` (web) or `GET /api/admin/v1/deployment` (admin, readable by every console role); `formatMoney` / `formatPrice` truncate the decimal string to the currency's minor units and let `Intl.NumberFormat` pick the symbol and grouping. Constraints: no currency symbol in locale strings (amounts are formatted before interpolation), InputNumber precision follows `minorUnits`, an unknown currency renders a plain number. See `docs/reference/i18n.md`.
- **Server-side money text carries the ISO code, never a symbol.** `money_label` / `price_label` (`core/money.py`) render "100.00 CNY"; error `params` holding amounts are pre-labelled so the catalogs stay currency-neutral; CSV headers say `Amount (USD)` from a `{currency}` template; `as_amount` quantizes to the deployment currency's minor unit. Constraint: no `¥` / `$` / `元` in backend strings or error catalogs — symbols belong to the consoles' `Intl` formatting. See `docs/reference/billing.md`. <!-- cjk-ok -->
- **English is the source language; zh-CN is a translation.** `core/messages.py` holds the English error catalog and exports `en-US/errors.json`; `zh-CN/errors.json` is hand-maintained under a key/placeholder parity test. The consoles fall back to en-US, the API client sends `Accept-Language`, and legal documents resolve through a locale chain that starts at the compliance profile's default (`none` → en-US, `cn` → zh-CN). Constraints: English drafts of the legal documents are seeded as unpublished templates, never auto-published; tests assert `code` / `message_key`, not rendered text.
- **Identity verification is a provider protocol keyed by the compliance profile.** `account/kyc.py` defines `KycProvider.verify(KycSubject) -> KycResult`; `kyc_provider` (only `aliyun_mobile3` today) selects the implementation, the profile's `kyc_form` selects the form (`cn_id_card` = PRC ID with checksum) and no form means 409 on submit and an inert recharge gate. Constraints: providers raise `KycRegionUnsupported` (400) when they cannot verify a subject instead of guessing; the platform stores the verified name, the masked identity, its keyed digest, the provider name and reference, and the status / timestamp (`users.kyc_*`), never the plaintext identity number. See `docs/reference/account.md`.
- **CAPTCHA is a provider enum (`captcha_provider` turnstile | aliyun, default turnstile), no mock.** The server verifies through the selected provider (`core/captcha.py`), `/auth/captcha-config` tells the web app which SDK to load, and the web CSP allow-lists both providers' origins so the switch needs no frontend rollout. Constraint: the `captcha_enabled` prod gate and its credential warning follow the selected provider.
- **Delivery channels are provider enums with one sanctioned mock each.** `sms_provider ∈ {mock, aliyun, twilio}`, `email_provider ∈ {mock, smtp}`; `mock` is prod-forbidden and the only stand-in (alongside `payment_mock` and `k8s_backend=fake`). The SMS protocol is kind-based (`verify` / `notice`): provider template codes stay inside the Aliyun channel, Twilio and email render bodies from `app/core/verification/templates.py` per locale. Constraint: a new provider = one enum value + its credential keys in the channel group + a `compute_config_warnings` completeness rule; never a second mock. Metric `superdl_verification_sent_total{channel, purpose}`.
- **Security features are switches, not mock providers.** CAPTCHA, identity verification and admin MFA are `*_enabled` booleans (platform config, security group); only third parties the flow cannot complete without keep exactly one stand-in each (`sms_provider=mock` / `email_provider=mock` / `payment_mock` / `k8s_backend=fake`), all refused in prod. Prod forbids switching security features off through the online write path (`SettingSpec.prod_forbidden`); CAPTCHA / identity verification / verification-before-recharge additionally have a boot compliance gate under the `cn` profile (`prod_gate=True` on the same spec — config-page red flag, boot fail-fast and write guard all derive from that one declaration). Constraint: `captcha_token` on `/auth/verification-code` is optional (400 when missing while CAPTCHA is on).
- **Stopped instances keep their SSH NodePort; pool occupancy is a metric.** Stopping does not release the port (the port survives a restart); `superdl_ssh_port_pool_ports{state}` is refreshed by the reconciler every round, with `SshPortPoolLow` / `SshPortPoolExhausted` alerts; long-stopped instances free their port through retention reclamation. See `docs/reference/limits.md`.
- **The number of accounts per verified identity is capped.** A passed verification stores the keyed digest `users.kyc_identity_hmac` (`crypto.hash_kyc_identity`; the plaintext is never stored); when the number of non-deleted accounts with the same digest reaches `real_name_max_accounts_per_identity` (default 3) the request gets 409; `superdl_user_signup_total` and `superdl_verification_sent_total` feed the abuse alert group. See `docs/reference/account.md`.
- **The database application role is separate from the owner, and connection strings use verify-full.** api / worker use the DDL-less `superdl_app` (`balance_ledger` append-only, `audit_log` immutable); the migration Job mounts `superdl-db-migrate` (owner); the self-signed CA is mounted through the ConfigMap `superdl-db-ca` and `sslrootcert` in the connection string is turned into an SSLContext by `db._split_db_tls`. Constraint: the migration Job and the backup CronJob are pinned to infra nodes with the same anchor as the other platform components. See `deploy/pg/README.md`, `deploy/app/secrets.example.yaml`.
- **Every K8s object the platform creates must pass its own admission policies.** Managed Job templates set `hostUsers: false` explicitly; CI renders the five instance shapes and three Job kinds plus their derived Pods with `scripts/render_admission_probes.py` and `--dry-run=server` while the policies are still installed, and only then removes them for the bare kind smoke test. See `docs/reference/orchestrator.md`.
- **Prod boot validation checks providers and placeholders, not credential completeness; a real cluster is not tied to prod.** `_validate_prod` refuses mock providers (SMS / email / payment / fake K8s), infrastructure placeholders and weak secrets, a non-https `web_base_url` when payment secrets are mounted, and an enabled Alipay channel without `alipay_seller_id` (the full list is in `docs/reference/security.md`); credential completeness is left to the runtime channel factories, which fail closed. The combined constraint `real_name_required_for_recharge ⇒ real_name_enabled` holds in every environment (`_validate_invariants` and the write-side `_check_real_name_invariant` agree); a missing `alertmanager_token` and a `prometheus_url` pointing at localhost are boot WARNINGs; dev + real may coexist. Constraint: the edge guard `edge_guard` is always on in prod with no switch, and production-like environments run as prod.

## Orchestration and platform

- **Policy parameters and platform configuration share one registry, and the read side is strongly typed.** Operational policies (disk price / grace days / quotas / discounts / preemption grace …) are the `policy` group of the platform configuration center, in the same `SETTING_SPECS` and the same `platform_settings` table as channel credentials and security switches; `get_runtime_config(session)` returns a `RuntimeConfig` (bool / int / Decimal / str per kind) and business code never compares string dictionaries to `"true"`. Constraints: a new setting = one `SettingSpec` + one `RuntimeConfig` field + a same-named `Settings` default (a unit test locks the three together); `/policies` (ops) accepts only the policy group and `/platform-config` (admin) refuses it; prod-forbidden values, the boot compliance gate and the config-page red flags all derive from the spec's `prod_forbidden` / `prod_gate`, no separate lists.
- **Module public surfaces are explicit and dependencies point one way.** `orchestrator/service.py` depends on `billing/service.py` (creation debits, conversion settlement); billing reaches back only through `orchestrator/queries.py` (read-only) and `orchestrator/transitions.py` (`transition` primitive, `system_stop` / `freeze_instance` / `unfreeze_instance` / `reclaim_frozen` / `stop_all_for_user`, data-disk arrears chain `arrears_transition_disks`), neither importing billing. Constraint: new "things billing needs orchestration to do" go into `transitions.py` with settlement injected as a callback (e.g. `settle_pending`); no in-function import of `orchestrator.service` inside billing; `account/deletion.py` and `account/sshkeys.py` stay independent of `account/service.py` (which billing depends on). See the import-linter contracts in `apps/api/pyproject.toml` and `tests/test_import_order.py`.
- **The reconciler works in two phases.** Inside the transaction it only transitions / marks / enqueues; K8s actions run after commit or through the outbox; failures are backstopped by leak reclamation's forced delete after the grace period. See `apps/api/app/modules/orchestrator/reconciler.py`.
- **Preemption orders by creation time only.** `created_at` newest first (ties by `id` descending), together with **same pool and model only** and **nothing is preempted unless enough can be freed**. Constraint: changing the ordering or candidate predicate in `preempt.pick_victims` **equals changing user-visible copy** and ships in the same commit. See `docs/reference/orchestrator.md`.
- **The preemption grace window is the outbox's delayed delivery.** `enqueue` in `apps/api/app/core/outbox.py` takes `delay_seconds`; the state machine moves to `stopping` immediately and the Pod is deleted when the delay expires. Constraint: the real ceiling of `spot_grace_seconds` is `creating_timeout_seconds − PREEMPT_TIME_RESERVE_SECONDS`, enforced by `validate_policy_value`'s cross-key check. See `docs/reference/limits.md`.
- **The worker is split into 5 component Deployments** (core / tenant-mgr / node-mgr / prewarm / disk-ops) with per-component least-privilege RBAC. Constraint: they are released as a set. See `deploy/README.md`, `deploy/app/k8s/03-worker.yaml`.
- **Control-plane HA and platform-component placement.** Public production requires 3 servers with stacked etcd + a VIP; platform components are placed by the `node-restriction.kubernetes.io/superdl-infra` label. That prefix is protected by the NodeRestriction admission plugin (pinned explicitly in both server configs' `kube-apiserver-arg`), kubelets cannot set it; the label is applied after installation by `deploy/ansible/site.yml` with admin credentials and the platform SA cannot change it (admission policy ③ allows only `superdl.io/*` and two named GPU operand keys). Constraint: the light tier (single-node k3s) is for pilots and integration only, never public production. See `deploy/cluster/README.md`.
- **Node pools switch seamlessly on empty nodes: a pool is just a label, no login, no reboot.** Switching happens only between `kata` / `hami` / `mig` (`cpu` is a physical property of GPU-less machines); prerequisites are **zero unreleased instances on the node** (`status != released`, including stopped), a model that supports the target pool (`core/gpu_models.supports_mig` for mig) and a ready target runtime. The desired pool lands in `node_specs.desired_pool` with the same desired-state semantics as `desired_unschedulable`, **overriding the enrollment record as the pool source of truth when set, and never cleared afterwards**. All pool-specific node software is delivered by DaemonSets keyed on labels (`kata-deploy` on `node-restriction.kubernetes.io/superdl-pool=kata`, the HAMi device plugin on `…=hami`, gpu-operator's vfio-manager and sandbox plugins on `gpu.deploy.*` derived from `workload.config`); vfio bind / unbind for passthrough is done by vfio-manager at runtime (`bind --all` on start, `unbind --all` in preStop). Constraints: ① convergence writes **the pool's complete label set** (`core/gpu_adapter.pool_node_labels`, including removal of stale keys), and admission policy ③'s Node-label allow-list adds only the two **named** keys `nvidia.com/gpu.workload.config` and `nvidia.com/gpu.deploy.device-plugin`, never the `nvidia.com/*` prefix — new keys are documented here first; ② switching does not uncordon automatically, operators uncordon after verifying placement; ③ decommissioning shares the same instance gate with a `force` bypass. See `docs/reference/nodes.md` and `deploy/cluster/runbooks/node-pool-switch.md`.
- **IOMMU is part of the node baseline for every GPU pool, with no per-pool branching.** Constraint: x86_64 writes the GRUB argument by CPU vendor (Intel `intel_iommu=on iommu=pt`, AMD / Hygon `amd_iommu=on iommu=pt`, unknown vendors fail closed unless `SUPERDL_JOIN_IOMMU_ARGS` is set), aarch64 writes no cmdline; the criterion is always a non-empty `/sys/kernel/iommu_groups`, empty means one reboot; the cpu pool (no GPU) skips the whole step.
- **The pool label has one writer, the platform; nodes never declare themselves.** `node-join.sh` writes no pool label; nodes enrol unlabelled and the reconciler applies the full label set when it judges the node Ready, moving to `joined` only after the labels succeed. Constraints: ① the reconciler must fetch nodes with `include_unlabeled`; ② a label failure does not advance state (retried next round) — "joined without a pool label" must never exist; ③ there is no "enrollment failed because of a pool-label mismatch" path, and `superdl_node_pool_label_mismatch_total` means "labels differ **and** the node is still schedulable"; ④ unlabelled nodes are fixed by patrol C2 and not counted in that metric.
- **The pool label moved into the NodeRestriction-protected prefix: the key is `node-restriction.kubernetes.io/superdl-pool`; the old key `superdl.io/pool` is only ever deleted.** `superdl.io/*` is outside NodeRestriction's protection, so a kubelet holding the shared agent token could label itself into a pool with `--node-label` and attract DaemonSets and tenant Pods. Constraints: ① the key comes only from `core/k8s/base.POOL_NODE_LABEL`, and cluster-side DaemonSet nodeSelectors / admission policy ③ / preflight change with it; ② the desired set from `pool_node_labels` always contains `LEGACY_POOL_NODE_LABEL: None`; ③ a non-infra node with no pool label, no enrollment row and no desired pool is cordoned automatically by patrol B2 and reported by `superdl_node_unenrolled`, never "auto-adopted"; ④ `cluster_join_token` accepts only agent tokens; the server node-token form is rejected both in the configuration center and in `node-join.sh`.
- **Node decommissioning is an `ops` action, not admin-only.** Same tier as cordon / force-stop / force-reclaim; irreversibility is carried by the mandatory reason plus the audit trail. Constraint: "which nodes may be deleted" is defined by admission policy ⑦ (control-plane / etcd / infra nodes refused), not by RBAC; join-token rotation and kubelet certificate revocation are control-plane actions the platform does not perform, and the response copy says so explicitly. See `docs/reference/nodes.md`.
- **Destroying an instance disk issues TRIM.** TopoLVM lvmd `issue_discards=1`.
- **Data disks are CephFS (Rook), one PVC per disk, the PVC size is the hard quota.** Hard prerequisite: tenant Pods always run `hostUsers: false` (userns), so the mounted filesystem must support idmapped mounts — cephfs does, NFS / SMB / 9p / GFS2 and JuiceFS (FUSE) do not and must not replace it. The quota is effective at creation: `disk.provision` creates / grows the PVC, `disk.deprovision` deletes it (the CSI destroys the subvolume); no wipe job, no subpath validation, no CLI image. Constraints: OSDs land on TopoLVM Block PVCs and share the VG with instance disks; on unified-memory machines the RAM Ceph consumes reduces sellable GPU memory (see `deploy/cluster/runbooks/hardware-notes.md`); the `rook-ceph` namespace is on admission policy ④'s exemption list (like `topolvm-system`); a deviceSet must set anti-affinity on both `placement` and `preparePlacement` (only one of them deadlocks PVC against OSD). See `deploy/cluster/values/rook-ceph-cluster.yaml` and `docs/reference/disks.md`.
- **The image registry is Harbor, with its parameters in the configuration center.** `registry_host / registry_project / registry_robot_name / registry_robot_secret (encrypted) / registry_ca_pem / registry_proxy_projects` and `image_allowed_registries` live in the platform config registry group; the registry address of the platform's own images (api / web / admin) is a deployment-side value. Constraint: the allow-list is not a prod boot gate (the Harbor address is allowed automatically; an empty list only yields a config warning).
- **Pull credentials are managed by the platform as imagePullSecrets.** `image_ref` stores the fully qualified Harbor name (no logical names); before creating instance Pods / prewarm Jobs the worker writes the dockerconfigjson Secret `superdl-registry-pull` into `superdl` and each tenant namespace by fingerprint (`ensure_pull_secret`), and Pods / Jobs reference it through `imagePullSecrets`; node registries.yaml keeps only the Spegel / CA / proxy-cache mirrors. Constraint: rotation = saving the new secret in the configuration center; changing the Harbor domain needs a bulk SQL update of `images.image_ref` (instance snapshots are untouched).
- **Platform image tags are semantic and re-pushable; catalog `image_ref` pins the digest.** A tag only expresses "framework version + CUDA line + Python"; `images.image_ref` is always `<repo>:<tag>@sha256:<digest>`. Constraints: after a re-push the admin console swaps the image ref to the new digest, `admin_update_image` clears node cache rows in the same transaction and the patrol prewarms the new ref; instance Pods and prewarm Jobs keep `IfNotPresent`; an instance's ref is a creation-time snapshot, so image fixes apply to new instances only.
- **The hardening baseline leaves the `SYS_CHROOT` / `SETUID` / `SETGID` capabilities to SSH.** Companions: the entrypoint runs `chmod g-w,o-w /root` before starting sshd; the pre-push self-check really connects over SSH once.
- **In the light tier, the server that doubles as GPU node runs the same node-join command.** When the script finds the local `k3s.service` / `rke2-server.service` running it skips the three agent steps; `--uninstall` on the server does not run the distribution's uninstall script. Constraints: the server's instance-disk VG must be created by hand before helmfile; `canonical_gpu_model` recognises `CMP<digits>HX` (the model taken from the lspci bracket name). See `docs/reference/nodes.md`.
- **Both tiers install the same GPU stack: light also gets gpu-operator and kata-deploy.** Differences are `deploy/cluster/values/light/` overrides (light only adds `toolkit.enabled=false`). Operand placement labels (hami pool `nvidia.com/gpu.deploy.device-plugin=false`, kata pool `nvidia.com/gpu.workload.config=vm-passthrough`) are delivered by the platform together with the pool label during enrollment reconciliation and pool-switch convergence. Constraint: tier availability depends only on "a Ready node in the pool + the runtime in place"; single-node light has one pool label.
- **`helmfile apply` is wrapped by `deploy/cluster/apply.sh`.** Both switches every time: `HELM_DIFF_USE_UPGRADE_DRY_RUN=true`, `--skip-diff-on-install`.
- **Both tiers use Cilium as the CNI.** CNI, NetworkPolicy, kube-proxy replacement, `kubernetes.io/egress-bandwidth` limits and Hubble observability have the same semantics in both tiers. Constraints: k3s's `flannel-backend: none` / `disable-network-policy: true` / `disable-kube-proxy: true` are server flags that **must be set at installation**; with kubeProxyReplacement `k8sServiceHost` must be the server's real IP (light overrides it in `values/light/cilium-light.yaml`). Tenant SSH NodePort traffic is SNATed from the ingress node's `cilium_host` (dynamically allocated from the Pod subnet), so address-based allow rules cannot match it and the CCNP in `deploy/cluster/cilium-policies.yaml` allows it by identity. See `deploy/cluster/README.md`.
- **DCGM collection is tiered: light collects at device level; the exporter image is pinned to 4.8.3.** Constraint: the node label is the lowercase `hostname`; `prom.py`'s `DCGM_NODE_LABEL` and the two GPU alerts' `$labels.hostname` are hard-coded lowercase.
- **A chart default of `0` makes helm upgrade fail; pin the equivalent explicitly in values.** kube-prometheus-stack's `prometheusSpec.maximumStartupDurationSeconds` is pinned to 900. Review new releases the same way.
- **The light-tier TopoLVM controller runs 1 replica.**
- **Tiers collapse to dedicated / shared / cpu; the isolation mechanism is dispatched by node pool.** `skus.tier` only expresses the sales category; the isolation mechanism is dispatched by `pool_label` (kata / mig / hami). The user-visible "shared · standard / shared · economy" derives from the pool (mig = hard-partitioned standard, hami = soft-partitioned economy). Constraints: legal pairs are enforced by `TIER_POOLS` in `apps/api/app/core/gpu_adapter` plus `apps/api/app/modules/catalog/service.py::_check_tier_pool`; the admin form only lets operators pick the display tier; "change pool" is available only while delisted; an `unknown pool` fails closed.
- **The HAMi pool is a cost optimisation, not a security boundary.** The hami pool provides **software limits / performance isolation**, not multi-tenant security isolation. Operators may restrict the shared tier to MIG with `SUPERDL_SHARED_TIER_ALLOWED_POOLS`, or inform users through the frontend consent modal. Also recorded in the isolation-level table of `reference/security.md`.
- **CPU-only instances are the third tier `tier=cpu` and may land in the hami pool.** Each GPU node is capped by the policy `gpu_node_cpu_instance_vcpu_cap` (default 16, 0 = forbidden), which is an **inventory criterion only**, never sent to the scheduler. Constraints: ① in `build_gpu_request` the `gpu_count == 0` decision comes **before the pool branch**, and the delivery gate uses the same criterion (CPU instances get an empty `schedulerName`); ② `build_pod_spec` states explicitly "GPU tiers scale by GPU count, CPU tier factor is always 1", never `max(1, gpu_count)`.
- **CPU-instance billing units are computed in `billing_units` in `apps/api/app/core/money.py`; the meaning of `price_hourly` is unchanged.** amount = `unit price × units × seconds / 3600`, `billing_units(gpu_count) = gpu_count or 1`. Constraints: every "unit price × units" goes through `billing_units` and `hourly_cost`; the `price_hourly` semantics are written in `docs/reference/catalog.md` (GPU SKU = per-GPU hourly price, CPU SKU = per-machine hourly price); bill rows store `gpu_count=0` as is.
- **DNS01 goes through acme-dns, enabled per tier.** The cluster holds only an account that can edit the `_acme-challenge` subdomain's TXT records. Constraint: the light tier sets `acmeDns.enabled=false` and the wildcard certificates (`superdl-jupyter-wildcard-tls` and `superdl-svc-wildcard-tls`) are loaded into the `superdl` namespace by hand. See `deploy/cluster/runbooks/acme-dns.md`.
- **Cluster configuration keys are distribution-neutral.** Keys are `cluster_*`; the distribution is derived by probing gitVersion; there is no `k8s_distro` key.
- **No Sentry-style SaaS.** Uncaught exceptions become a uniform 500 with a trace and alert through Loki / Prometheus.
- **Admin monitoring is drawn in-house; Grafana is only a link.** No iframes; an unset `grafana_url` shows a one-line hint.
- **The admin component health deep probe is the second read-only exception to "no K8s calls on the request path".** The patrol snapshot (60 s) gives component status bits; the deep probe adds Pod-level failure reasons, Warning events and certificate expiry dates on the spot without persisting them. Constraints: read-only, no DB writes, no audit; a hard 5 s timeout plus 120 calls per admin per hour; every failure is 503 and the frontend falls back to the snapshot; admin ops / readonly only, never the user console; the ClusterRole gains read access to `events` and `cert-manager.io/certificates`. Judgement and fact assembly stay in `app/core/k8s/health.py`; the deep probe never changes status bits.
- **Component health copy has one source, the two consoles' locales; the backend emits facts only.** The backend sends structured `{key, value, tone}` facts: `value` is pure data (counts / versions / object names / addresses), while labels, criteria and impact map from the key in the locales; `fix_hint` and `diag_hint` are commands and do not vary by language. Constraint: a new fact key is added to `apps/admin/i18next.config.ts`'s `preservePatterns` (otherwise `removeUnusedKeys` deletes dynamically read keys).
- **Alert `runbook_url` is set only on rules with a dedicated runbook.** For the others the first step is in the summary and in the index table of `deploy/cluster/runbooks/README.md`.
- **The only north-south entry is Gateway API + Envoy Gateway.** `GatewayClass superdl` + one `Gateway superdl` (namespace `superdl`) with 6 listeners (`http` / `api-https` / `console-https` / `admin-https` / `app-https` / `svc-https`) + 4 platform-domain HTTPRoutes and one 80→443 redirect; tenant Jupyter and service endpoints get **one HTTPRoute per instance** in the tenant namespace, crossing namespaces through `allowedRoutes.namespaces.from: Selector` + `superdl.io/managed=true`. Constraint: `gatewayAPI` stays false in `deploy/cluster/values/cilium.yaml`.
  - **The CRD channel is fixed at first install (experimental).** CRD lifecycle is handled in one place, `deploy/cluster/gateway-api-crds.sh` (charts always run `crds.enabled=false`); the script has a channel pre-check and `deploy/cluster/preflight.sh` re-verifies it.

Per-IP rate limits use `BackendTrafficPolicy` with `sourceCIDR.type: Distinct`, the source-IP allow-list uses `SecurityPolicy.authorization` (`defaultAction: Deny` + `clientCIDRs`), and all three assume `externalTrafficPolicy: Local`. See "限流分层" in `docs/reference/security.md`. <!-- cjk-ok -->
  - The ingress coordinates are the three constants in `apps/api/app/core/k8s/base.py`; `cluster_status.gateway_ready` means the Gateway object reports `Programmed=True`; everything that identifies the ingress by namespace (NetworkPolicy sources, admission exemptions) uses `envoy-gateway-system`.

  See `deploy/cluster/README.md`, `deploy/app/k8s/04-gateway.yaml`.

- **A deployed service is its own aggregate root; instances are its immutable revisions.** `services` stores only identity and gateway-side attributes (`public_slug`, `require_api_key`, `desired_state`, the current / candidate instance pointers, a revision counter); the service state is **derived, never persisted**, from `desired_state` plus the state and readiness of the current / candidate instance. Every deployment = a new instance, with `instances.service_id` pointing back. **Billing, quotas, reclamation, the reconciler and the migration listener still act on instances**; service-level operations delegate to the row-level functions of `orchestrator.service`, and orchestrator never depends on services or reads the `services` table. Constraints: instance-level lifecycle endpoints (stop / start / restart / DELETE) answer 409 for service instances, the purchase-mode endpoints work as usual; `POST /instances` accepts no service fields; a revision update in v1 is recreate only (the endpoint answers 503 meanwhile; slug / URL / API key unchanged) and is not offered to subscription services; there is still one HTTPRoute per instance, `rollout_instance_id` is reserved for blue-green. See `docs/reference/services.md`.

Constraint: **auth results are never cached**, so the control plane is a synchronous dependency of every public endpoint. See `docs/reference/services.md`.
- **Deploying a service and creating an instance have separate entry points and share no page.** The market checkout bar has one CTA, "Next: configure instance", and only builds dev boxes; services are entered only from the "Online services" page and the command palette at `/services/new`, where the spec is chosen inside the deployment page.
