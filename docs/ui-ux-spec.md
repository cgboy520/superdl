# SuperDL UI/UX 规格

两端(`web` 用户控制台 / `admin` 管理控制台)的信息架构、逐屏交互规则与视觉约定。文案规范见 [`copy-style-guide.md`](./copy-style-guide.md),前端契约见 [`reference/web.md`](./reference/web.md) 与 [`reference/admin.md`](./reference/admin.md)。

## 1. 全站交互规则

1. **CTA 即库存**:主页价格墙卡片主按钮直接写「可开实例 N」/「已租完」(禁用态),库存数字在按钮里;市场表格用「可开实例」列 + 售罄行灰置表达同一件事。
   SKU `available_count` 是近似可开实例数(共享档含超卖系数,后端台账签名缓存估算),**不是物理空闲卡数**;页面一律用「可开实例/台」表述,禁止换算成「卡」。
2. **条件操作与预留功能一律可见但禁用 + tooltip 说明原因**:操作菜单永不隐藏条目;灰置时 tooltip 写清前置条件(如「关机后才能释放实例」)或「即将上线」。未实现的能力不进 UI。
3. **价格公式摊开**:计费项 × 单价 × 数量逐行列出;**「日常费用」单独一栏**(关机也扣的钱:数据盘)。
4. **关机 ≠ 释放,多级删除防护**:关机与释放是两个动作;释放需二次确认并复述实例 ID(名称)+ 勾选「我确认将清除实例盘全部数据(数据盘不受影响)」才解锁红色按钮。
5. **风险商品知情同意**:下单「共享·经济档」弹 modal 逐条列明软件隔离共享、算力为均值保障、性能可能波动、可能被重调度,确认才放行。
6. **给等待路径,不给死胡同**:库存不足给「换个档位」引导;创建失败给「重新创建」按钮与失败原因。

## 3. 用户端

### 3.1 信息架构

```
公开层    /(首页,未登录默认落地页;已登录照常显示,顶栏切「进入控制台」)· /login · /help · /legal/terms · /legal/privacy
控制台(全宽顶栏 + 浅色侧栏)
├─ 概览      /dashboard   # 实例数/余额/今日消费/未读通知 + 公告与预警横幅 + 快捷入口
├─ 算力市场  /market      ← 未登录可看,下单跳登录
├─ 容器实例  /instances   ← 登录后默认落地页
├─ 存储      /storage     # 数据盘 + 挂载全景
├─ 费用中心  /billing     # 余额/充值/账单/收支明细
└─ 账户设置  /settings    # SSH 公钥 / 通知阈值 / 实名 / 账号(改密·登出)
创建实例     /market/create/:skuId   ← 全页路由,不用弹窗
```

### 3.2 首页与登录

**主页 `/`**:public 顶栏(logo | 算力市场 / 价格 #pricing / 算力排名 #ranking | 登录 / 免费注册);Hero 单帧渐变 + 右侧数据卡
(最低时价 / 可开实例数),不做轮播;快捷入口四宫格全部指向真实能力;**GPU 价格墙**用 `/skus` 公开端点(60s 轮询),卡片与市场页
同构,接口失败整区降级为「前往算力市场」入口、不开天窗;**算力排名**由 `packages/ui/src/gpuSpecs.ts` 静态表驱动(Tabs 半精/单精
+ 横向百分比条,在售型号带跳价格墙的标记,脚注「理论峰值算力」)。页面数字一律取真实数据;三栏页脚(产品/支持/合规)带防挖矿声明,ICP 与公安备案号取自 `/site-config`,缺失则不渲染。

**登录 `/login`**:分屏。左 45% 品牌渐变区(logo / 返回首页 / 口号 / 三条卖点 bullets,lg 以下隐藏),右白底居中三态 Segmented
表单(验证码 / 密码 / 注册,+86 前缀),密码态经「忘记密码」进第四态重置密码。`?redirect=` 回跳仅接受 `/` 开头且非 `//` 开头的站内路径。

### 3.3 屏 ① 算力市场

- 页头合规警示条(禁挖矿声明,色走 token)。「计费方式」chips:`按量计费`(选中)|`包日`/`包周`/`包月`(disabled + tooltip)
  +「计费规则」链接(modal)。筛选链 chips 行:`GPU 型号`(每项后缀 `可开 N`,客户端聚合各 SKU available_count)|`档位`(四档)
  |`显存` | `GPU 数量`(1/2/4/8,按 `max_gpus_per_instance ≥ n` 过滤;空闲不足 n 的行不过滤掉,改为灰置)。前三行首位为「全部」。
- **SKU 表格(radio 单选)**,列:选择 | 规格名 + 档位徽标(经济档 hint「性能可能波动」在 Tooltip)| GPU 型号/显存(共享档写清份额与算力 %)
  | 可开实例(>0 绿数字 / =0「已租完」标签)| 实例配置 vCPU·内存 | 实例盘 | 最高 CUDA(tooltip)| 价格(单卡,钉右列)`¥X.XX/时` 大号。空闲不足所选卡数的行:radio 禁用 + 行灰置,不隐藏。
- **底部通栏结算条(sticky,与创建页共用 CheckoutBar)**:规格汇总 + `配置费用 ¥X.XX/时`(明细 popover 摊开公式)+ 未登录
  「登录后租用」/ 已登录「下一步:配置实例」(未选中禁用带 tooltip)。
- 未登录可浏览全部内容;30s 轮询;空态「没有符合条件的规格,试试放宽筛选」。

### 3.4 屏 ② 创建实例

全页单栏卡片流,非向导步进;`?gpus=N` 承接市场页选择。卡片分区:

1. `计费方式`:同 §3.3 chips。
2. `已选规格`:SKU 单行表格回显(市场同列去掉「空闲 GPU」)+ `GPU 数量` chip(1/2/4/8,受 SKU 上限)+「更换规格」链接。
3. `镜像`:三枚 Tab —— **平台镜像**(级联:框架 → 框架版本 → Python → CUDA,标注「已在节点预热,秒级启动」)/ **自定义镜像**
   (只有仓库地址一栏,注明镜像须内置 SSH 22 与 JupyterLab 8888、私有仓库凭据联系客服配置)/ **我的镜像**(disabled + tooltip)。
4. `数据盘(可选)`:「不需要 / 新建 / 挂载已有盘」;「新建」为行内直建(名称 + 容量滑块,单价来自 `/policies` 折日展示;先建盘
   再建实例,建盘成功而建实例失败须提示「数据盘已创建并开始计费,可在存储页管理」);说明:独立于实例、关机与释放均保留、**关机也计费**。
5. `SSH 密钥`:选择已有公钥(多选);无密钥时行内添加小表单(不支持密码登录)。
6. `实例名称`(可选,默认生成)。

底部 CheckoutBar 在 §3.3 基础上加「日常费用 ¥X/日」栏(注释:关机也会产生,数据盘),明细 popover 逐行摊开(单价 × 卡数;盘价
GB·月折日;注明计费依据为实例事件流水);余额不足时按钮变「余额不足,去充值」;主按钮「创建并开机」,经济档先弹知情同意 modal,创建带 Idempotency-Key。

### 3.5 屏 ③ 容器实例列表

- 页头:标题 + 常驻策略提示条(「停止的实例欠费冻结 72 小时后将回收实例盘,数据盘不受影响」)+ 工具行
  (`租用新实例` 主按钮 / 刷新 / `密钥登录设置`(→ /settings#ssh)/ 搜索框,客户端过滤 name/uuid)。
- 表格 7 列:①`名称 / ID`(可改名)+「详情」链接(双击行同效);②`状态` 徽标 + 行内附加信息(冻结态附红色回收倒计时;failed 态
  展开失败原因,未运行过的再给绿色 `未扣费` 标签与 `重新创建` 按钮,运行过的注「按实际运行结算」);③`规格详情` GPU 型号 × 数量
  + 档位徽标,popover 展开完整配置;④`GPU 利用率` 迷你 sparkline(近 1h,running 时;`GET /api/v1/metrics/instances` 批量端点,
  45s 独立轮询)+ 末值 %,断源时灰字「监控暂不可用」而页面其余正常;⑤`计费` = `按量` 标签 + `¥X.XX/时 × N 卡` + 第二行 `今日
  ¥Y.YY`(`/bills/daily-summary`,60s 轮询);⑥`快捷工具`(竖排)`SSH` 一键复制指令 + `JupyterLab` 直达 + `实例监控`,非 running 灰置带 tooltip;⑦`操作` `开机` `关机` `更多 ▾`,全部条目常显,灰置用 tooltip 写明原因。
- 「更多 ▾」:可用 = `重启` / `事件记录` / `释放实例`(红);预留(disabled)= `无卡模式开机` / `保存镜像` /
  `转包年包月`。不放:更换镜像 / 重置系统 / 升降配置 / 修改 SSH 密码(密钥制)/ 扩缩数据盘(归存储页)。
- 不做的列:地区 / 主机号、本地磁盘 %、镜像状态、付费方式独立列、释放时间独立列(倒计时在②)。
- 关机二次确认:说明按量实例关机后 GPU 释放、再开机可能库存不足;释放走规则 4 的多级防护。

### 3.6 屏 ④ 实例详情

- 头部:名称 / 状态徽标 / 档位 + 操作组(同列表)+ 关键信息条(ID / 规格 / 单价 / 今日消费 / 创建时间)。
- Tab **监控**(默认):四张 ECharts 曲线卡 —— GPU 利用率 / 显存占用 / CPU / 内存;1h/6h/24h;非 running 提示暂无实时监控,断源
  (503)显示「监控数据暂不可用,不影响计费」。**连接**:SSH 卡片(完整登录指令 + 复制 + 仅密钥登录说明)+ JupyterLab 卡片(打开
  按钮 + token 重置)。**事件**:状态迁移时间线(时间 / 事件 / 操作者 / 计费影响),明示「此记录即计费依据」。**账单**:该实例小时账单表。
- 危险区(页尾):释放实例(红,多级防护)。

### 3.7 屏 ⑤ 费用中心

- 余额卡:`可用余额` 大数字 + `充值` 主按钮 + 低余额预警阈值设置(输入 + 保存按钮);策略要求实名才可充值而账号未实名时,页头给实名横幅。
- 充值 modal:金额档位 + 自定义;渠道 Tab 由平台配置的可用渠道驱动(未开通的 disabled + tooltip,开发环境可用「模拟支付」)→
  真二维码(antd QRCode 渲染 qr_url)+ `expires_at` 倒计时 + 2s 轮询自动确认(到终态即停);到账切成功态,倒计时归零显示「订单已过期」。
- 消费概览:本月 GPU 时费 / 日常费用(数据盘)/ 今日消费 + 按实例的成本占比环图。账单 Tab:`小时账单`(时间/实例/时长/单价×卡数/
  金额)| `收支明细`(充值/消费/退款/调账,余额快照,游标「加载更多」)| 导出 CSV(按当前 Tab 口径,客户端生成:循环游标拉全量,
  BOM 头,金额保持字符串)。

### 3.8 屏 ⑥ 存储

- 顶部「挂载全景图」横条(自绘 DOM):`/`(实例盘·随实例回收·免费)· `/root/data`(数据盘·¥X/GB·月·独立保留)。**只列真实
  挂载点**:后端 Pod 只挂这两处,不得宣传未实现的挂载点。
- 数据盘列表(页头「新建数据盘」按钮 → modal:名称 + 容量,实时折日估算):名称 / 容量 / 计费(每盘快照价 `price_gb_month`,折日小字)/ 状态 / 到期·回收(active→「按日扣费中」;grace→
  「宽限期(只读)剩 X 天」;frozen→「冻结中,X 天后清除」;deadline 由 `grace_started_at`/`frozen_started_at` + `/policies`
  天数前端计算)/ 挂载中的实例 / 创建时间 / 操作(`扩容` 抽屉(滑块 + 差价)、`删除` 多级防护)。
- 无「续费」按钮:余额按日扣费制,无预付到期概念。回收策略透明:欠费 → 7 天宽限(只读)→ 冻结 30 天 → 清除,列表行倒计时。
  空态引导:「数据盘独立于实例,释放实例不丢数据」。

### 3.9 状态与文案体系(两端共用,收进 `packages/ui`)

- 状态枚举 → 徽标色 / antd Badge 语义 / 文案 key 的单一映射表(`status.ts`);倒计时统一 `剩 Xh`(天级用 `formatDaysLeft`:`剩 X 天`);
  金额统一 `¥1,234.56`;时长统一 `X 小时 Y 分`(`format.ts`)。
- 文案走 i18n,namespace 划分与闸门见 [`reference/i18n.md`](./reference/i18n.md);GPU 公开规格(TFLOPS/架构)静态表 `gpuSpecs.ts`。

## 4. 管理端

### 4.1 信息架构与角色

导航:运营总览 `/` · 节点与 GPU `/nodes` · 集群 `/cluster` · SKU 与定价 `/skus` · 镜像与预热 `/images` · 租户与实例 `/tenants`
· 财务对账 `/finance` · 审计日志 `/audit` · 平台配置 `/platform` · 系统设置 `/settings`。
角色:admin(全部)/ ops(资源+实例)/ finance(财务区可写 —— 调账发起与复核、订单核验与补单,其余只读)/ readonly(全站只读)。

高危操作(强制停止 / 冻结·解冻租户 / cordon·uncordon / 吊销注册令牌 / 忽略死信)统一走 `ReasonAction`:原因必填 → 二次确认 → 审计落库;调账原因必填,且要求第二管理员复核才入账,发起人不能自审。

### 4.2 逐屏要点

- **运营总览**:KPI 行(今日收入含昨日对照 / 本月收入 / 今日新注册带环比箭头 / 活跃实例 / 付费租户 / 告警数);主图表「实际
  超卖率 vs 真实利用率」按池并置(柱 = 实际超卖率,折线 = 24h 平均利用率,60%/85% 阈值辅助线);GPU 池占用堆叠条(按节点池
  标签分组,已租 / 空闲两段);右栏实时告警流;有死信时在 KPI 下方展开任务死信卡(重放 / 忽略,忽略需原因)。
- **节点与 GPU**:待入网节点卡(池/主机名/备注/状态/阶段/心跳/错误 + 重新生成加入命令 / 吊销)与「添加节点」生成一次性加入命令;
  节点表(名称/池标签/GPU 型号×数量/显存/已用/驱动/CUDA/vCPU/内存/磁盘/状态/操作 `cordon`·`uncordon`,原因必填、经 outbox 执行;
  `drain` 只是灰置占位 + tooltip 说明经集群 Runbook 执行);点节点行 → 该节点每卡热力网格(tooltip 给 util%/显存/温度)+ 节点级 ECharts 曲线(每卡 util 与显存,1h/6h/24h,24h XID 计数以红标显示),配了 `grafana_url` 才多一个外链按钮。
- **SKU 与定价**:SKU 表(名称/卡型/档位/切分规格/容量卡数/已售/实际超卖/算力超卖×/显存超卖×/单价/上架开关/编辑),在架而容量
  为 0、实际超卖已达设定上限时标红;编辑抽屉全参数表单 + 超卖风险提示(「变更仅影响新实例;显存超卖 >1.2 需二次确认」)+ 编辑
  必填原因,右侧实时容量预览(匹配节点 / 可用 GPU / 总 GPU / 预估实例数 + 警告);新建可「从集群资源创建」带出推荐参数。
- **租户与实例**:两个 Tab。租户表(ID/手机脱敏/余额/累计消费/实例数/数据盘 GB/状态/注册时间;手机号可检索,`冻结`/`解冻` 原因
  必填)+ 点行开账单下钻侧滑(余额与累计消费摘要 + `小时账单`/`资金流水` 两 Tab,与用户端同源);全局实例表按状态/实例名/节点名
  过滤(实例名/归属/节点/状态/规格/SSH 端口/创建时间),操作 `强制停止`(原因必填,仅 running,下发关机并结算尾账);`驱逐重调度` 为占位按钮,非经济档或非 running 时禁用,可点时也只提示当前版本未开放。
- **财务对账**:日对账卡(可选日期)`事件计费合计` vs `指标估算合计`(usage_hourly 推算)+ diff%,diff > 2% 标红并列出差异实例;
  Tab 充值流水(状态与订单号检索,只读)| 调账(发起 → 双人复核 → 入账)| 异常清单(丢回调 / 关单 / 负余额,可渠道核验与补单,补单原因必填;负余额只给提示不给动作)| 审计。
