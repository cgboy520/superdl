# SuperDL · 用户端 / 管理端 UI-UX 规格

> 用户端参照 AutoDL 的交互范式(基于 2026-08 对其生产环境前端的逐项盘点),管理端为自设计。
> 本文是 WP10/WP11 的实现规格;高保真示意图见配套 design canvas(11 画板)。
> **红线:只借鉴交互模式,所有品牌、文案、视觉为 SuperDL 原创,不照抄 AutoDL 措辞。**

---

## 1. 设计原则(从 AutoDL 盘点提炼 + 我们的差异化)

### 1.1 照搬的六条铁律

| # | 原则 | 落地 |
|---|---|---|
| 1 | **CTA 即库存** | 市场卡片主按钮直接写「N 卡可租」/「已租完」(禁用态),库存数字就在按钮里,不让用户点了才知道没货 |
| 2 | **条件操作可见但禁用 + tooltip 说明原因** | 实例操作菜单永不隐藏条目;灰置时 tooltip 写清前置条件(如「关机后才能释放实例」)。这是 AutoDL 全站最值得学的一条 |
| 3 | **价格公式摊开** | 创建页右侧常驻价格栏:计费项 × 单价 × 数量逐行列出;**「日常费用」单独一栏**(关机也扣的钱:数据盘)——账单争议的头号来源必须前置讲清 |
| 4 | **关机 ≠ 释放,多级删除防护** | 关机与释放是两个动作;释放需二次确认并复述「实例 ID(名称)」+ 勾选「我确认将清除实例盘全部数据(数据盘不受影响)」才解锁红色按钮 |
| 5 | **风险商品知情同意** | 下单「共享·经济档」时弹 modal 逐条列明:软件隔离共享、算力为均值保障、性能可能波动、可能被重调度;确认才放行。既是商业诚信也是纠纷防火墙 |
| 6 | **给等待路径,不给死胡同** | 库存不足时给「换个档位/地区」引导(P1 加订阅空闲 GPU);创建失败给「重新创建」按钮与失败原因 |

### 1.2 超越 AutoDL 的四点(我们的体验卖点)

1. **SKU 制市场**:按「GPU 型号 × 档位」聚合成规格卡片,而非 AutoDL 的"逐台主机挑选"——选择成本更低,且贴合我们 K8s 统一调度的库存模型(用户不该关心具体主机)。
2. **统一存储页**:AutoDL 有 6 层存储、3 种计费口径、互斥规则藏在深处;我们只有 3 层,用一张「挂载全景图」一屏讲清(路径/生命周期/价格/关机是否计费)。
3. **回收政策全透明**:冻结 72h→回收的倒计时在列表行、详情页、站内信三处一等公民展示;AutoDL 的释放期限要靠用户自己记。
4. **计费依据可自查**:实例详情的「事件时间线」就是计费流水(状态迁移 = 计费边界),配合监控曲线,数据透明是最好的客服(原方案 §5.4 的产品化)。

## 2. 视觉与主题

| | 用户端 `web` | 管理端 `admin` |
|---|---|---|
| 基调 | 浅色,清爽企业风 | **深色 NOC 风**(运维值班室气质) |
| 主色 | 靛蓝 `#4F46E5`(有意避开 antd 默认蓝与 AutoDL 品牌蓝) | 同主色,深底上用亮青 `#22D3EE` 作数据强调、琥珀 `#F59E0B` 作告警 |
| 实现 | antd 6 ConfigProvider token(`colorPrimary` 等),token 定义放 `packages/ui` 两端共享 | antd `theme.darkAlgorithm` + 自定义背景 `#0B1220` 系 |
| 字体 | 系统栈 + 数字用 tabular-nums(金额/端口/利用率对齐) | 同左,监控数值可用等宽 |
| 布局 | 左侧固定导航(200px)+ 顶栏(余额入口/通知/用户菜单) | 同构局,顶栏加「环境徽标」(生产/预发)与全局告警铃 |
| 状态色 | running 绿 / creating·starting 蓝(动效) / stopped 灰 / frozen 橙 / failed·releasing 红 | 同一套语义色,深色版调亮 |

## 3. 用户端(参照 AutoDL)

### 3.1 信息架构

```
控制台 /console
├─ 概览          # 轻量:实例数/余额/预警/快捷入口(参照 AutoDL 主页分区,做减法)
├─ 算力市场      /market          ← 未登录可看,下单跳登录
├─ 容器实例      /instances       ← 默认落地页
├─ 存储          /storage         # 统一页:数据盘 + 挂载全景 + 公共模型缓存说明
├─ 费用中心      /billing         # 余额/充值/账单/收支明细
└─ 账户设置      /settings        # SSH 公钥 / 安全 / 通知阈值 / 实名(预留)
创建实例 /market/create/:skuId    ← 全页路由(AutoDL 同款,不用弹窗)
```

### 3.2 屏 ① 算力市场

- 顶部筛选行:`计费方式`(MVP 仅按量,控件预留)|`GPU 型号`|`档位`(独享整卡 / MIG 切分 / 共享·标准 / 共享·经济)|`显存`。
- **SKU 卡片网格**(3~4 列),卡片字段:
  - 档位徽标(四色区分;经济档附「性能可能波动」小标)
  - GPU 型号 + 显存(如 `RTX 4090 · 24G`;共享档写清份额:`1/2 卡 · 8G 显存 · 50% 算力(均值)`,经济档 7G——显存配额 × 单卡实例数必须 ≤ 物理显存 × 显存超卖率,数字要能对账)
  - 每实例配置:vCPU / 内存 / 实例盘(含 100G)
  - 驱动 / CUDA 最高版本(tooltip 解释)
  - 价格:`¥X.XX/时`,数字大号
  - CTA:**「N 卡可租」**(主按钮)/「已租完」(禁用)
- 页脚合规条:禁止挖矿等违规用途声明(链接用户协议)。
- 空态:「没有符合条件的规格,试试放宽筛选」。

### 3.3 屏 ② 创建实例(全页,左表单右价格栏)

左侧分区(非向导步进,单页滚动,AutoDL 同构):
1. `已选规格`:SKU 摘要卡(可返回换)+ `GPU 数量`(chip:1/2/4/8,受 SKU 上限)
2. `镜像`:Tab 两枚——**平台镜像**(级联:框架 → 框架版本 → Python → CUDA;标注「预热镜像,秒级启动」)/ **自定义镜像**(仓库地址输入 + 可选 pull secret;帮助链接)
3. `数据盘(可选)`:「不需要 / 新建(容量滑块,¥X/GB·月) / 挂载已有盘(下拉)」;说明:独立于实例、关机与释放均保留、**关机也计费**
4. `SSH 密钥`:选择已有公钥(多选)/ 新增;无密钥时内联引导(不支持密码登录,安全说明)
5. `实例名称`(可选,默认生成)

右侧常驻价格栏(sticky):
- 明细行:实例(¥/时 × N 卡)| 数据盘(¥/GB·月,折日展示)
- **「开机费用」与「日常费用」分栏**(后者注释:关机也会产生)
- 余额显示;不足时按钮变「余额不足,去充值」
- 主按钮「创建并开机」;经济档先弹知情同意 modal(§1.1-5)

### 3.4 屏 ③ 容器实例列表

- 页头:标题 + 常驻策略提示条(「停止的实例欠费冻结 72 小时后将回收实例盘,数据盘不受影响」)+ 工具行(`租用新实例` 主按钮 / 搜索 / 列设置)。
- 表格列(antd Table,支持列设置,ID 与操作列锁定):
  1. `名称 / ID`(可改名)
  2. `状态`:徽标 + 行内附加标签(`余额不足预警` 橙 / `冻结·剩 47h` 红倒计时 / `创建失败可重试`)
  3. `规格`:GPU 型号 × 数量 + 档位徽标;popover 展开完整配置
  4. `GPU 利用率`:迷你 sparkline(近 1h,running 时)
  5. `计费`:`¥X.XX/时` + 今日消费
  6. `连接`:`SSH` 一键复制指令按钮 + **`JupyterLab`** 直达按钮(仅 running)
  7. `操作`:`开机` `关机` `更多 ▾`(重启 / 释放 / 事件记录)——全部条目常显,灰置带 tooltip 原因
- 关机二次确认:说明按量实例关机后 GPU 释放、再开机可能库存不足(AutoDL 同款心智);释放走 §1.1-4 多级防护。

### 3.5 屏 ④ 实例详情

- 头部:名称/ID/状态徽标/档位 + 操作组(同列表)+ 关键信息条(created_at / 计费起点 / 今日消费)。
- Tab:
  - **监控**(默认):ECharts 曲线组——GPU 利用率、显存占用、(共享档加)算力份额说明线;CPU/内存/网络;时间范围 1h/6h/24h;数据来自 Prometheus 代理接口,断源时显示「监控暂不可用,不影响计费」
  - **连接**:SSH 卡片(host/port/指令复制/密钥列表)+ JupyterLab 卡片(打开按钮 + token 重置)
  - **事件**:状态迁移时间线(时间/事件/操作者/计费影响)——**明示"此记录即计费依据"**
  - **账单**:该实例小时账单表
- 危险区(页尾):释放实例(红,多级防护)。

### 3.6 屏 ⑤ 费用中心

- 余额卡:`可用余额` 大数字 + `冻结` 小字 + `充值` 主按钮 + 低余额预警阈值设置入口。
- 充值 modal:金额档位 + 自定义;渠道 Tab(微信支付 / 支付宝)→ 二维码 + 倒计时 +「已完成支付」;结果态成功/超时/失败。
- 消费概览:本月消费额、按实例/按 SKU 的成本占比环图(超越点:成本归因,AutoDL 只有流水)。
- 账单 Tab:`小时账单`(时间/实例/SKU/时长/金额)| `收支明细`(充值/消费/退款/调账,余额快照)| 导出 CSV。

### 3.7 屏 ⑥ 存储(统一页,差异化)

- 顶部「挂载全景图」横条(自绘 SVG/DOM):
  `/(实例盘·含100G·随实例回收·免费)` · `/root/data(数据盘·¥X/GB·月·独立保留)` · `/public/models(模型缓存·只读·免费)`
- 数据盘列表:名称/容量/已用(配额)/挂载中的实例/到期时间/操作(`扩容`(抽屉,滑块+差价)、`续费`、`删除`(多级防护))。
- 到期策略透明:到期 → 7 天宽限(只读)→ 冻结 30 天 → 清除,列表行倒计时。
- 空态引导:「数据盘独立于实例,释放实例不丢数据」——把留存设计讲成用户利益。

### 3.8 状态与文案体系(两端共用,收进 `packages/ui`)

- 状态枚举 → 徽标色/图标/中文名的单一映射表;倒计时统一 `剩 Xh` 格式;金额统一 `¥1,234.56`;时长统一 `X 小时 Y 分`。
- 所有 tooltip 文案集中 `copy.ts` 管理(便于 AI 一致修改与后续 i18n)。

## 4. 管理端(自设计,深色 NOC 风)

### 4.1 信息架构与角色

```
/admin
├─ 运营总览        # 值班首屏
├─ 节点与 GPU      # 物理资源
├─ SKU 与定价      # 商品与超卖参数
├─ 租户与实例      # 客户与全局实例
├─ 财务对账        # 钱
├─ 审计日志        # 谁干了什么
└─ 系统设置        # 告警阈值/回收参数/公告
角色:admin(全部) / ops(资源+实例) / finance(财务只读+调账发起) / readonly
```

高危操作(强制停机/驱逐/调账/冻结租户)一律:原因必填 → 二次确认 → 审计落库;调账额外要求第二管理员复核通过才生效。

### 4.2 屏 ⑦ 运营总览

- KPI 行:今日收入 / 本月收入 / 活跃实例 / 付费租户 / 今日新注册(环比小箭头)。
- **镇店图表:「实际超卖率 vs 真实利用率」双曲线**(共享池,按池切换;辅助线:P95 利用率、上调/回调阈值 60%/85%)——原方案称之为"这门生意最重要的仪表盘",放 C 位。
- GPU 池占用条:整卡/MIG/共享标准/经济 各池 已租/空闲/维护 堆叠条。
- 右栏:实时告警流(级别色点 + 时间 + 一句话,点击进 Grafana)+ 今日大事(注册/开通/回收/失败)。

### 4.3 屏 ⑧ 节点与 GPU

- 节点表:名称/池标签/GPU 型号×数量/驱动/CUDA/K8s 状态/HAMi 或 Kata 标记/操作(`cordon` `drain` `维护标记`,均需原因)。
- 选中节点 → **每卡热力网格**:每张卡一格,显示 util% / 显存% / 温度,XID 异常红框闪烁;点击格子 → 该卡上的实例列表(跨租户)。
- 下方 Grafana 嵌入区(iframe,DCGM 大盘改造版):节点级历史曲线,免自研。

### 4.4 屏 ⑨ SKU 与定价

- SKU 表:名称/卡型/档位/切分规格(1/2 卡·8G 等)/算力超卖×/显存超卖×/单价/状态/池内库存(容量·已售·**实际超卖率**)。
- 编辑抽屉:全参数表单;超卖参数区带黄色风险提示(「变更仅影响新实例;显存超卖 >1.2 需二次确认」);上架/下架开关。
- 库存视图:每池「物理容量 / 已售额度 / 实际超卖率」三数字 + 近 7 天趋势 sparkline(定价决策的抓手)。

### 4.5 屏 ⑩ 租户与实例

- 租户表:ID/手机(脱敏)/余额/累计消费/实例数/数据盘 GB/状态/注册时间;操作:`冻结`/`解冻`(原因必填)、查看详情。
- 租户详情侧滑:余额与流水摘要 / 实例列表 / 审计足迹。
- 全局实例表(跨租户):支持按节点/SKU/状态过滤;操作:`强制停止`(通知用户)、`驱逐重调度`(**仅限经济档**,按钮对其他档禁用+tooltip 说明)。

### 4.6 屏 ⑪ 财务对账

- 日对账卡:`事件计费合计` vs `指标估算合计`(usage_hourly 推算)+ **diff%**;diff>2% 标红并列出差异实例清单——这是"事件为主、指标对账"策略的产品化落点。
- Tab:充值流水(渠道/单号/状态/回调时间,可手动补单)| 小时账单(可下钻到事件流水)| 调账(发起 → 复核 → 生效,全程留痕)| 异常清单(回调丢失/结算缺口/负余额)。

## 5. P1 借鉴清单(来自 AutoDL 盘点,MVP 后按呼声排期)

| 功能 | 备注 |
|---|---|
| 无卡模式开机 | AutoDL 粘性最强功能(0 卡低价待机装环境);我们实例盘为节点本地 LV,需 pin 原节点实现 |
| 包日/周/月计费 + 批量续费 | 账单模型已预留 duration 维度 |
| 保存镜像 / 克隆码 / 跨实例拷贝 | 镜像存储与配额体系随 Harbor 后置项一起评估 |
| 订阅空闲 GPU / 排队创建 | 售罄常态化后的留客通道 |
| 学术资源加速「开关」 | 做成实例详情的 toggle(AutoDL 只有命令行,是其可超越点) |
| 成本护栏:月预算上限 / 空闲自动关机 | 行业空白,建议尽早,差异化卖点 |
| Web 终端(`@xterm/xterm` 6) | 详情页内嵌终端,依赖 kubectl-exec 代理通道 |
