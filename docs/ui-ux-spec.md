# SuperDL · 用户端 / 管理端 UI-UX 规格

> 用户端参照 AutoDL 的交互范式(基于 2026-08 对其生产环境前端的逐项盘点;WP13 重设计时以实况截图二次核准),管理端为自设计。
> 本文是 WP10/WP11 的实现规格;WP13(公开主页/布局壳/逐屏 AutoDL 化)已同步修订本文,见 `docs/specs/WP13-autodl-redesign.md`。
> **红线:只借鉴交互模式,所有品牌、文案、视觉为 SuperDL 原创,不照抄 AutoDL 措辞。**

---

## 1. 设计原则(从 AutoDL 盘点提炼 + 我们的差异化)

### 1.1 照搬的六条铁律

| # | 原则 | 落地 |
|---|---|---|
| 1 | **CTA 即库存** | 市场卡片主按钮直接写「N 卡可租」/「已租完」(禁用态),库存数字就在按钮里,不让用户点了才知道没货 |
| 2 | **条件操作可见但禁用 + tooltip 说明原因** | 实例操作菜单永不隐藏条目;灰置时 tooltip 写清前置条件(如「关机后才能释放实例」)。这是 AutoDL 全站最值得学的一条 |
| 3 | **价格公式摊开** | 创建页右侧常驻价格栏:计费项 × 单价 × 数量逐行列出;**「日常费用」单独一栏**(关机也扣的钱:数据盘)——账单争议的头号来源必须前置讲清 |
| 4 | **关机 ≠ 释放,多级删除防护** | 关机与释放是两个动作;释放需二次确认并复述「实例 ID(名称)」+ 勾选「我确认将清除实例盘全部数据(数据盘不受影响)」才解锁红色按钮 |
| 5 | **风险商品知情同意** | 下单「共享·经济档」时弹 modal 逐条列明:软件隔离共享、算力为均值保障、性能可能波动、可能被重调度;确认才放行。既是商业诚信也是纠纷防火墙 |
| 6 | **给等待路径,不给死胡同** | 库存不足时给「换个档位/地区」引导(P1 加订阅空闲 GPU);创建失败给「重新创建」按钮与失败原因 |

### 1.2 超越 AutoDL 的四点(我们的体验卖点)

1. **SKU 制市场**:按「GPU 型号 × 档位」聚合成规格卡片,而非 AutoDL 的"逐台主机挑选"——选择成本更低,且贴合我们 K8s 统一调度的库存模型(用户不该关心具体主机)。
2. **统一存储页**:AutoDL 有 6 层存储、3 种计费口径、互斥规则藏在深处;我们只有 3 层,用一张「挂载全景图」一屏讲清(路径/生命周期/价格/关机是否计费)。
3. **回收政策全透明**:冻结 72h→回收的倒计时在列表行、详情页、站内信三处一等公民展示;AutoDL 的释放期限要靠用户自己记。
4. **计费依据可自查**:实例详情的「事件时间线」就是计费流水(状态迁移 = 计费边界),配合监控曲线,数据透明是最好的客服(原方案 §5.4 的产品化)。

## 3. 用户端(参照 AutoDL)

### 3.0 屏 ⓪ 公开主页与登录(公开层,WP13 新增)

**主页 `/`**(未登录默认落地页;已登录访问照常显示,顶栏切「进入控制台」,不自动跳转——AutoDL 同款心智):
- 顶栏(public 态):logo | 算力市场 / 价格(#pricing) / 算力排名(#ranking) | 登录 / 免费注册。
- Hero:**单帧**深靛渐变 + 网格纹理 + 右侧玻璃拟态数据卡(最低时价/空闲卡数,真实数据)。不做轮播——AutoDL 3 帧承载多产品线,我们单产品,轮播空转显山寨。
- 快捷入口四宫格(对位 AutoDL,全部指向真实能力):快速开始 / GPU 选型(#ranking) / 透明计费(/billing) / 数据无忧(/storage)。
- **GPU 价格墙**(#pricing):实时 `/skus` 数据(公开端点,60s 轮询),Tab「整卡独享 / 切分与共享」;卡片与市场页同构(型号+显存/TierTag/TFLOPS(静态表)/vCPU·内存/大号时价/CTA 即库存);接口失败整区降级为「前往算力市场」入口,不开天窗。
- **算力排名**(#ranking):`packages/ui/src/gpuSpecs.ts` 静态表(厂商公开白皮书口径)驱动,Tabs 半精/单精 + 横向百分比条 + 前三序号徽;在售型号標「在售」;脚注「理论峰值算力」。
- CTA 横幅(真实空闲卡数,不编造数字)+ 三栏页脚(产品/支持/合规,含防挖矿声明与备案占位)。

**登录 `/login`**(分屏):左 45% 品牌渐变区(logo/返回首页/口号「GPU 算力,即开即用」/三条卖点 bullets;lg 以下隐藏),右白底居中三态表单(验证码/密码/注册,+86 前缀)。支持 `?redirect=` 回跳(仅接受 `/` 开头且非 `//` 开头的站内路径)。

### 3.1 信息架构

```
公开层
├─ 首页  /            ← 见 §3.0
└─ 登录  /login
控制台(全宽顶栏 + 浅色侧栏,§2 布局)
├─ 概览          /dashboard      # 轻量:实例数/余额/今日消费/预警/快捷入口
├─ 算力市场      /market          ← 未登录可看,下单跳登录
├─ 容器实例      /instances       ← 登录后默认落地页
├─ 存储          /storage         # 统一页:数据盘 + 挂载全景 + 公共模型缓存说明
├─ 费用中心      /billing         # 余额/充值/账单/收支明细
└─ 账户设置      /settings        # SSH 公钥 / 安全 / 通知阈值 / 实名(预留)
创建实例 /market/create/:skuId    ← 全页路由(AutoDL 同款,不用弹窗)
```

### 3.2 屏 ① 算力市场(WP13:AutoDL 式筛选链 + SKU 表格单选)

- 页头合规警示条(禁挖矿声明,对位 AutoDL 红色合规条,色走 token)。
- 卡片「计费方式」:chips `按量计费`(选中)|`包日`/`包周`/`包月`(**disabled + tooltip「即将上线」**,预留控件)+「计费规则」链接(modal)。
- 卡片「选择规格」:
  - 筛选链 chips 行:`GPU 型号`(每项后缀 `空闲 N`,客户端聚合各 SKU available_count;`空闲/总数` 分式待后端 total_count,P1)|`档位`(四档)|`显存`|`GPU 数量`(1/2/4/8,选中后按 `max_gpus_per_instance ≥ n && available_count ≥ n` 过滤)。
  - **SKU 表格(radio 单选,对位 AutoDL「选择主机」表)**,列:选择 | 规格名 + 档位徽标(经济档附「性能可能波动」)| GPU 型号/显存(共享档写清份额与算力 %)| 空闲 GPU(>0 绿 / =0 灰)| 实例配置 vCPU·内存 | 实例盘(含 100G)| 最高 CUDA(tooltip)| 价格(单卡)`¥X.XX/时` 大号。
  - **库存 0 行:radio 禁用 + 行灰置 +「已租完」标签,不隐藏**(铁律 #1/#2)。
- **底部通栏结算条(sticky,与创建页共用 CheckoutBar)**:规格汇总 + `配置费用 ¥X.XX/时`(明细 popover 摊开公式)+ 未登录「登录后租用」/ 已登录「下一步:配置实例」(未选中禁用带 tooltip)。
- 未登录可浏览全部内容;30s 轮询;空态:「没有符合条件的规格,试试放宽筛选」。

### 3.3 屏 ② 创建实例(全页,单栏卡片流 + 底部结算条;WP13 由左右分栏改版)

卡片分区(非向导步进,单页滚动,AutoDL 同构;`?gpus=N` 承接市场页选择):
1. `计费方式`:同 §3.2 chips(按量选中,包周期预留禁用)
2. `已选规格`:SKU 单行表格回显(与市场表格同列,AutoDL「选择主机」观感)+ `GPU 数量`(chip:1/2/4/8,受 SKU 上限)+「更换规格」返回市场
3. `镜像`:Tab 三枚——**平台镜像**(级联:框架 → 框架版本 → Python → CUDA;标注「预热镜像,秒级启动」)/ **自定义镜像**(仓库地址输入 + 可选 pull secret;帮助链接)/ **我的镜像(disabled + tooltip「保存镜像功能上线后开放」,P1 预留)**
4. `数据盘(可选)`:「不需要 / 新建 / 挂载已有盘(下拉)」;**「新建」为行内直建**(名称 + 容量滑块,单价来自 `/policies` 折日展示;提交时先建盘再建实例,建盘成功而建实例失败须提示「数据盘已创建并开始计费,可在存储页管理」);说明:独立于实例、关机与释放均保留、**关机也计费**
5. `SSH 密钥`:选择已有公钥(多选);**无密钥时行内添加小表单**(不支持密码登录,安全说明)
6. `实例名称`(可选,默认生成)

底部通栏结算条(sticky,CheckoutBar):
- **「日常费用 ¥X/日」(注释:关机也会产生,数据盘)与「配置费用 ¥X/时」分栏**,费用明细 popover 逐行摊开(单价 × 卡数;盘价 GB·月折日;注明计费依据为实例事件流水)
- 余额显示;不足时按钮变「余额不足,去充值」
- 「取消」/ 主按钮「创建并开机」;经济档先弹知情同意 modal(§1.1-5);创建带 Idempotency-Key

### 3.4 屏 ③ 容器实例列表

- 页头:标题 + 常驻策略提示条(「停止的实例欠费冻结 72 小时后将回收实例盘,数据盘不受影响」)+ 工具行(`租用新实例` 主按钮 / 刷新 / `密钥登录设置`(→/settings#ssh)/ 搜索框(客户端过滤 name/uuid);列设置列入 P1)。
- 表格 7 列(WP13 定稿):
  1. `名称 / ID`(可改名)+「详情」链接(双击行同效)
  2. `状态`:徽标 + 行内附加标签(`余额不足预警` 橙 / `冻结·剩 47h` 红倒计时 / `创建失败可重试`)
  3. `规格详情`:GPU 型号 × 数量 + 档位徽标;popover 展开完整配置
  4. `GPU 利用率`:迷你 sparkline(近 1h,running 时;数据来自 `GET /api/v1/metrics/instances` 批量端点,45s 独立轮询)+ 末值 %;**断源时灰字「监控暂不可用」,页面其余正常**
  5. `计费`:`按量` 标签 + `¥X.XX/时 × N 卡` + 第二行 `今日 ¥Y.YY`(来自 `/bills/daily-summary`,60s 轮询)
  6. `快捷工具`(竖排,对位 AutoDL):`SSH` 一键复制指令 + **`JupyterLab`** 直达 + `实例监控`(→详情监控 Tab);非 running 灰置带 tooltip
  7. `操作`:`开机` `关机` `更多 ▾`——全部条目常显,灰置用 antd Tooltip 写明原因
- 「更多 ▾」菜单:可用 = `重启` / `事件记录` / `释放实例`(红);**预留(disabled+「即将上线」)= `无卡模式开机` / `保存镜像` / `转包年包月`**(三者均在 §5 P1 有排期背书);不放:更换镜像/重置系统/升降配置(无 roadmap)、修改 SSH 密码(密钥制决策)、扩缩数据盘(归存储页)。
- 明确不做的 AutoDL 列:地区/主机号(无此概念不伪造)、本地磁盘 %(无数据源)、镜像状态(无数据)、付费方式独立列(恒按量并入⑤)、释放时间独立列(倒计时在②)。
- 关机二次确认:说明按量实例关机后 GPU 释放、再开机可能库存不足(AutoDL 同款心智);释放走 §1.1-4 多级防护。

### 3.5 屏 ④ 实例详情

- 头部:名称/ID/状态徽标/档位 + 操作组(同列表)+ 关键信息条(created_at / 计费起点 / 今日消费)。
- Tab:
  - **监控**(默认):ECharts 曲线组——GPU 利用率、显存占用、(共享档加)算力份额说明线;CPU/内存/网络;时间范围 1h/6h/24h;数据来自 Prometheus 代理接口,断源时显示「监控暂不可用,不影响计费」
  - **连接**:SSH 卡片(host/port/指令复制/密钥列表)+ JupyterLab 卡片(打开按钮 + token 重置)
  - **事件**:状态迁移时间线(时间/事件/操作者/计费影响)——**明示"此记录即计费依据"**
  - **账单**:该实例小时账单表
- 危险区(页尾):释放实例(红,多级防护)。

### 3.6 屏 ⑤ 费用中心

- 余额卡:`可用余额` 大数字 + `冻结` 小字 + `充值` 主按钮 + 低余额预警阈值设置(输入 + **保存按钮**,非仅回车)。
- 充值 modal:金额档位 + 自定义;渠道 Tab(`微信支付` / `支付宝` **disabled+tooltip「商户资质接入后开放」** / `模拟支付(开发环境)` 可用)→ **真二维码(antd QRCode 渲染 qr_url)** + `expires_at` 倒计时 +「已完成支付」轮询;结果态成功/超时/失败。
- 消费概览:本月消费额 + **今日消费**、按实例/按 SKU 的成本占比环图(超越点:成本归因,AutoDL 只有流水)。
- 账单 Tab:`小时账单`(时间/实例/SKU/时长/金额)| `收支明细`(充值/消费/退款/调账,余额快照)| **导出 CSV(客户端生成:循环游标拉全量,BOM 头,金额保持字符串)**。

### 3.7 屏 ⑥ 存储(统一页,差异化)

- 顶部「挂载全景图」横条(自绘 SVG/DOM):
  `/(实例盘·含100G·随实例回收·免费)` · `/root/data(数据盘·¥X/GB·月·独立保留)` · `/public/models(模型缓存·只读·免费)`
- 数据盘列表(WP13 定稿):名称 / 容量 / **计费**(每盘快照价 `price_gb_month`,折日小字)/ 状态 / **到期·回收**(active→「按日扣费中」;grace→「宽限期(只读) 剩 X 天」;frozen→「冻结中,X 天后清除」;deadline 由 `grace_started_at`/`frozen_started_at` + `/policies` 天数前端计算)/ 挂载中的实例 / 创建时间 / 操作(`扩容`(抽屉,滑块+差价)、`删除`(多级防护))。
- 注:`已用量`列待后端上报(P1);**无`续费`按钮**——我们是余额按日扣费制,无预付到期概念(与 AutoDL 计费模型差异,有意为之)。
- 回收策略透明:欠费 → 7 天宽限(只读)→ 冻结 30 天 → 清除,列表行倒计时。
- 空态引导:「数据盘独立于实例,释放实例不丢数据」——把留存设计讲成用户利益。

### 3.8 状态与文案体系(两端共用,收进 `packages/ui`)

- 状态枚举 → 徽标色/图标/中文名的单一映射表;倒计时统一 `剩 Xh` 格式(天级用 `formatDaysLeft`:`剩 X 天`);金额统一 `¥1,234.56`;时长统一 `X 小时 Y 分`。
- 所有 tooltip 文案集中 `copy.ts` 管理(便于 AI 一致修改与后续 i18n);WP13 新增键:`comingSoon`(预留功能统一话术)、计费规则说明、渠道未开放原因、数据盘直建残留提示等。
- 营销文案(主页/登录/页脚)集中 `packages/ui/src/marketing.ts`;GPU 公开规格(TFLOPS/架构)静态表 `packages/ui/src/gpuSpecs.ts`(理论峰值口径,脚注声明)。

## 4. 管理端(自设计,深色 NOC 风)

### 4.1 信息架构与角色

```
/admin
├─ 运营总览        # 值班首屏
├─ 节点与 GPU      # 物理资源
├─ SKU 与定价      # 商品与超卖参数
├─ 租户与实例      # 客户与全局实例
├─ 财务对账        # 钱
├─ 审计日志        # 谁干了什么
└─ 系统设置        # 告警阈值/回收参数/公告
角色:admin(全部) / ops(资源+实例) / finance(财务只读+调账发起) / readonly
```

高危操作(强制停机/驱逐/调账/冻结租户)一律:原因必填 → 二次确认 → 审计落库;调账额外要求第二管理员复核通过才生效。

### 4.2 屏 ⑦ 运营总览

- KPI 行:今日收入 / 本月收入 / 活跃实例 / 付费租户 / 今日新注册(环比小箭头)。
- **镇店图表:「实际超卖率 vs 真实利用率」双曲线**(共享池,按池切换;辅助线:P95 利用率、上调/回调阈值 60%/85%)——原方案称之为"这门生意最重要的仪表盘",放 C 位。
- GPU 池占用条:整卡/MIG/共享标准/经济 各池 已租/空闲/维护 堆叠条。
- 右栏:实时告警流(级别色点 + 时间 + 一句话,点击进 Grafana)+ 今日大事(注册/开通/回收/失败)。

### 4.3 屏 ⑧ 节点与 GPU

- 节点表:名称/池标签/GPU 型号×数量/驱动/CUDA/K8s 状态/HAMi 或 Kata 标记/操作(`cordon` `drain` `维护标记`,均需原因)。
- 选中节点 → **每卡热力网格**:每张卡一格,显示 util% / 显存% / 温度,XID 异常红框闪烁;点击格子 → 该卡上的实例列表(跨租户)。
- 下方 Grafana 嵌入区(iframe,DCGM 大盘改造版):节点级历史曲线,免自研。

### 4.4 屏 ⑨ SKU 与定价

- SKU 表:名称/卡型/档位/切分规格(1/2 卡·8G 等)/算力超卖×/显存超卖×/单价/状态/池内库存(容量·已售·**实际超卖率**)。
- 编辑抽屉:全参数表单;超卖参数区带黄色风险提示(「变更仅影响新实例;显存超卖 >1.2 需二次确认」);上架/下架开关。
- 库存视图:每池「物理容量 / 已售额度 / 实际超卖率」三数字 + 近 7 天趋势 sparkline(定价决策的抓手)。

### 4.5 屏 ⑩ 租户与实例

- 租户表:ID/手机(脱敏)/余额/累计消费/实例数/数据盘 GB/状态/注册时间;操作:`冻结`/`解冻`(原因必填)、查看详情。
- 租户详情侧滑:余额与流水摘要 / 实例列表 / 审计足迹。
- 全局实例表(跨租户):支持按节点/SKU/状态过滤;操作:`强制停止`(通知用户)、`驱逐重调度`(**仅限经济档**,按钮对其他档禁用+tooltip 说明)。

### 4.6 屏 ⑪ 财务对账

- 日对账卡:`事件计费合计` vs `指标估算合计`(usage_hourly 推算)+ **diff%**;diff>2% 标红并列出差异实例清单——这是"事件为主、指标对账"策略的产品化落点。
- Tab:充值流水(渠道/单号/状态/回调时间,可手动补单)| 小时账单(可下钻到事件流水)| 调账(发起 → 复核 → 生效,全程留痕)| 异常清单(回调丢失/结算缺口/负余额)。
