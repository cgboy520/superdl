# Private-network gateways

Connects a tenant's own network (office, data centre, cloud VPC, SD-WAN POP) to the tenant's instances. One gateway = one platform-run Pod that dials the tenant's VPN endpoint (WireGuard, IPsec IKEv1/v2, OpenVPN, or an openconnect-family SSL VPN: AnyConnect / ocserv, Fortinet, GlobalProtect, Pulse / Ivanti, F5, Array) and relays TCP between the tunnel and the cluster. Instances keep their baseline security context; only the gateway Pod holds network privileges, in its own namespace. The image and its agent are in [deploy/netgw](../../deploy/netgw/README.md); the design choice is in [decisions.md](../decisions.md).

What a tenant gets:

| Direction          | Mechanism                                                                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Instance → network | Named forwards: instances connect to `<forward name>:<port>`; the gateway connects to `target_host:target_port` inside the tunnelled networks                            |
| Instance → network | SOCKS5 at `socks5h://<gateway name>:1080` (CONNECT only); host names resolve on the gateway, so split-DNS domains work; destinations must be inside the tunnelled ranges |
| Network → instance | Instance forwards: the tenant network connects to `<tunnel address>:<port>`; the gateway connects to the instance's `target_port`                                        |

Traffic leaves the gateway with the tunnel address as source, so the tenant side routes one address and never sees the cluster ranges; overlapping tenant ranges are independent (each gateway has its own network namespace).

## Data model

- `net_gateways`: `uuid` unique, `user_id`, `name` (DNS label, unique per user together with forward names), `protocol` (CHECK ∈ {wireguard, ipsec, openvpn, openconnect}), `status` (CHECK ∈ {active, deleting}), `config` jsonb (`remote_cidrs`, `local_address?`, `dns?`, `tunnel` = the non-secret protocol parameters), `secrets_encrypted` (AES-GCM JSON of keys / PSK / passwords / the OpenVPN profile, AAD `netgw:<uuid>`), `public_key?` (WireGuard, generated by the platform), `generation` / `applied_generation`, `tunnel_up`, `tunnel_changed_at?`, `pod_phase?`, `checked_at?`, `idempotency_key?` + `request_fingerprint?` (the fingerprint covers secret presence, never secret values)
- `net_gateway_forwards`: `gateway_id` (FK, cascade), `user_id`, `kind` (CHECK ∈ {intranet, instance}), `name` (unique per user), `port`, `target_host?` (intranet), `instance_id?` (instance), `target_port`; CHECK `(kind = 'intranet') = (target_host IS NOT NULL AND instance_id IS NULL)`; partial unique `(gateway_id, port) WHERE kind = 'instance'`

Derived `state` (not stored): `deleting` (status) → `applying` (`applied_generation < generation`) → `connected` / `disconnected` (`tunnel_up`, the gateway Pod's readiness = the agent's tunnel check).

## Contract

| Endpoint                                             | Role / auth              | Notes                                                                                                                                                                                             |
| ---------------------------------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/netgw/config`                           | user                     | `enabled` (= `SUPERDL_NETGW_IMAGE` set), `egress_ips` (for the tenant firewall), per-user and per-gateway limits, bandwidth, SOCKS port                                                           |
| `GET /api/v1/netgw/gateways`                         | user                     | Own gateways with forwards; secrets never returned (`has_password` / `has_preshared_key` flags only)                                                                                              |
| `POST /api/v1/netgw/gateways`                        | user                     | 201, `state=applying`; Idempotency-Key (replay 200 + `X-Idempotent-Replay`); identity verification when required (`netgw.realNameRequired`); 10/h per user; unavailable → 409 `netgw.unavailable` |
| `GET /api/v1/netgw/gateways/{uuid}`                  | user                     | Owner only, otherwise 404                                                                                                                                                                         |
| `PUT /api/v1/netgw/gateways/{uuid}`                  | user                     | Replaces the configuration; protocol fixed (`netgw.protocolImmutable`); a null secret keeps the stored one; the gateway Pod restarts with the new spec                                            |
| `DELETE /api/v1/netgw/gateways/{uuid}`               | user                     | 202, `state=deleting`; the outbox removes every object, then the row                                                                                                                              |
| `POST /api/v1/netgw/gateways/{uuid}/forwards`        | user                     | Body discriminated by `kind`; instance forwards accept the user's unreleased dev instances only                                                                                                   |
| `DELETE /api/v1/netgw/gateways/{uuid}/forwards/{id}` | user                     |                                                                                                                                                                                                   |
| `GET /api/v1/netgw/gateways/{uuid}/logs`             | user                     | Gateway container log, read-only and not audited: owner only, 20/h per user, 5 s K8s timeout, `tail_lines` ≤ 2000                                                                                 |
| `GET /api/admin/v1/netgw/gateways`                   | ops / finance / readonly | Every tenant's gateways (newest 500), `user_id` and `pod_phase` added                                                                                                                             |
| `POST /api/admin/v1/netgw/gateways/{uuid}/delete`    | ops                      | Reason required (audited); same teardown as the user's delete                                                                                                                                     |

Mutations other than create share a 60/h per-user bucket. Every write is audited with target `netgw:<uuid>`.

## Rules and invariants

### Input

- Tunnelled networks (`remote_cidrs`): 1–16 IPv4 networks, prefix /8 or longer, pairwise disjoint, never overlapping 0/8, 127/8, 169.254/16, 224/4, 240/4, `SUPERDL_TENANT_POD_CIDR` or `SUPERDL_TENANT_SERVICE_CIDR` (both must match the cluster).
- Tunnel address (`local_address`): required for WireGuard and IPsec, outside the reserved ranges; OpenVPN and openconnect take the server-assigned address (a value is rejected).
- Peer: a DNS name or a public IPv4 (`is_global`) outside the tunnelled networks; TCP peer ports (OpenVPN over TCP, openconnect) outside the tenant egress blocklist. The gateway NetworkPolicy blocks private destinations, so a name resolving to a private address cannot be reached either.
- No raw daemon configuration is accepted. WireGuard: peer key, optional PSK, endpoint, MTU; the gateway key pair is generated server-side and only the public key is shown. IPsec: PSK of 16–128 printable characters without `"` or `\`, identities from a fixed character set, proposal presets `default` / `compatible` / `modern`. OpenVPN: the client profile passes an allow-list (`modules/netgw/ovpn.py`, the agent keeps an identical copy and a test compares them): no scripts, plugins, file paths, management, routes, `redirect-gateway` or DNS options; inline `<ca>` / `<cert>` / `<key>` / `<tls-*>` blocks only. openconnect: `https://host[:port][/path]`, password on stdin, optional certificate pin.
- Names (gateway and forwards) are DNS-1035 labels of up to 40 characters and share one per-user name space: they become Services in the tenant namespace. Names that could collide with platform objects (32-hex prefixes, `netgw-`, `jupyter-`, `disk-`, `superdl-`, `kubernetes`) are reserved.
- Instance-forward listen ports avoid 53, 1080, 9101 and 20000–20063 (the agent's resolver, SOCKS, health and intranet-forward ports) and are unique per gateway.
- Limits: `SUPERDL_NETGW_MAX_PER_USER` gateways (default 2), `SUPERDL_NETGW_MAX_FORWARDS` forwards per gateway (default 16); see [limits.md](./limits.md).

### Convergence

- Every change bumps `generation` and enqueues `netgw.apply` in the same transaction. The handler (tenant-mgr worker) renders the **current** row into the agent spec, ensures the tenant namespace and the gateway pull Secret, and converges the objects; it records `applied_generation = max(applied, rendered)`. Deletion sets `deleting` and enqueues `netgw.delete`, which removes the objects in both namespaces and then the row (forwards cascade).
- Objects (`core/k8s/netgw.py`, all labelled `superdl.io/netgw=<uuid>`, never `superdl.io/managed`, which the instance reconciler would reclaim as leaked endpoints):

| Namespace       | Object                                                                                                                                                                                           |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `superdl-netgw` | Secret `netgw-<uuid>` (`spec.json`), Deployment `netgw-<uuid>`, NetworkPolicy `netgw-<uuid>`, Service `netgw-<uuid>` (SOCKS), Service `netgw-<uuid>-<forward id>` per intranet forward           |
| tenant          | ExternalName `<gateway name>` and `<forward name>` (pointing at the Services above), ClusterIP `netgw-<uuid>-<forward id>` per instance forward (selector `superdl.io/instance=<instance uuid>`) |

- Deployment: one replica, `Recreate`, the spec hash as a Pod annotation (any change restarts the Pod); `dnsPolicy: None` with `127.0.0.1` (the agent's dnsmasq); node selector `node-restriction.kubernetes.io/superdl-netgw=true` (kubelets cannot set it, so a tenant node cannot attract gateways); egress bandwidth `SUPERDL_NETGW_BANDWIDTH_MBPS` (default 100). Container: uid 0, `drop: [ALL]` + `NET_ADMIN` / `NET_BIND_SERVICE` / `MKNOD`, no privilege escalation, read-only root, RuntimeDefault seccomp, no service-account token, readiness `/healthz` (tunnel up), liveness `/livez`.
- The gateway patrol (30 s, tenant-mgr, advisory lock) reads Deployment and Pod state: sets `tunnel_up` / `pod_phase` / `checked_at`; re-applies (generation + 1) when nothing is pending and the Deployment is missing or runs another image than `SUPERDL_NETGW_IMAGE`; tears down gateways of deleted accounts; deletes Deployments without a row. Rows locked by a running task are skipped for that round.
- Instance forwards whose instance is released drop out of the rendered spec and are shown with `available=false`.
- The data plane does not depend on the control plane: stop-the-world releases leave gateways and tunnels running.

### Network boundary

- The tenant NetworkPolicy admits, in both directions, Pods in `superdl-netgw` labelled `superdl.io/tenant=<that namespace>` (set only by the platform); without a gateway the rule matches nothing.
- The gateway NetworkPolicy admits ingress from its tenant's namespace only (any port); egress to the cluster DNS, to the peer ports on the internet (private ranges excepted), and to its tenant's namespace (instance forwards). Decapsulated tenant traffic never crosses the Pod interface, so the platform policies apply to the tunnel's outer packets only.
- The agent connects forwards and SOCKS only to addresses inside `remote_cidrs` and reverse relays only to the Pod / Service ranges, so the gateway is never an egress proxy for the internet.
- The gateway only initiates: no public listener, no port pool. Tenants allow the addresses in `SUPERDL_NETGW_EGRESS_IPS` on their side.
- Admission: policy ① lets platform service accounts write in `superdl-netgw`; policy ④ (`superdl-global-pod-guard`) limits Pods there to the digest-pinned `…/superdl-netgw@sha256:` image, the three capabilities, no escalation, no token and only their own `netgw-*` Secret plus emptyDir volumes. The namespace is PSA `privileged` (NET_ADMIN is outside `baseline`) and carries no `superdl.io/managed` label.

### Enabling

1. Build and push the image ([deploy/netgw](../../deploy/netgw/README.md)); set `SUPERDL_NETGW_IMAGE` to the `…/superdl-netgw@sha256:…` reference (prod refuses tags) and `SUPERDL_NETGW_EGRESS_IPS` to the gateway nodes' public egress addresses.
2. On each gateway node load `wireguard`, `tun`, `xfrm_user`, `esp4` (`/etc/modules-load.d/superdl-netgw.conf`) and label it `node-restriction.kubernetes.io/superdl-netgw=true`.
3. Release; `superdl-netgw` and its RBAC come with `deploy/app/k8s`.

Gateways are not billed separately; the per-user and per-gateway limits and the bandwidth cap bound their footprint.
