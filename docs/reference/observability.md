# Observability and operations

Business metrics, request-id, health probes, alert rules and admin-drawn monitoring.

## Contract

| Endpoint                                                        | Role / auth                    | Notes                                                                                                                                                                                                                                                          |
| --------------------------------------------------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /metrics`                                                  | Bearer `SUPERDL_METRICS_TOKEN` | Prometheus scrape                                                                                                                                                                                                                                              |
| `GET /healthz`                                                  | anonymous                      | liveness: 200 as long as the process is alive, no dependency probe; not in openapi                                                                                                                                                                             |
| `GET /readyz`                                                   | anonymous                      | readiness: probes the DB and compares `alembic_version` with the code head, **must match exactly**; behind / ahead / unknown (503 `schema_mismatch`), never migrated (503 `never_migrated`), multiple heads (503 `multi_head`) take no traffic; not in openapi |
| `GET /api/admin/v1/nodes/{node_name}/metrics?range=1h\|6h\|24h` | ops/readonly                   | `{available, gpus:[{index, util:[[ts,v]], mem_used_mb, temp}], xid_count_24h}`; source down → `available=false` with 200                                                                                                                                       |
| `GET /api/admin/v1/alerts`                                      | ops/finance/readonly           | Alert feed                                                                                                                                                                                                                                                     |
| platform-config `observability` group                           | admin                          | `grafana_url` (`https?://`, may be empty), `oncall_phone` (critical platform alerts are additionally sent directly via outbox `notify.sms`; empty = disabled)                                                                                                  |

Business metrics live in `app/core/metrics.py`: dead letters, task timeouts, settlement failures and lag, unresolved settlement gaps (`superdl_settlement_gap_unresolved`, a DB-derived gauge, alert when > 0 for 15 minutes), fund/ledger discrepancies, per-phase patrol failures, leaked Pods and the circuit breaker, stuck instances, node loss, callback amount / currency mismatch, credit after order close, channel reversal notices and manual handling (`superdl_payment_reversal_resolved_total{action}`), per-order query failures, data-disk PVC provisioning dead letters, audit write failures, worker heartbeat, HTTP histogram (full route template), spot preemption count, SSH port pool level (`superdl_ssh_port_pool_ports{state}`, every reconciler round), negative-balance exposure (`superdl_wallet_negative_count` / `superdl_wallet_negative_sum`, every balance patrol round), platform config writes (`superdl_platform_config_write_total{domain}`).

Security-domain counters: `superdl_login_failed_total{actor_type}` (user / admin), `superdl_authz_denied_total{actor_type}` (authenticated but rejected by the role gate, 403), `superdl_admin_privilege_change_total` (account creation / role change / deactivation / password reset / MFA reset), `superdl_pii_reveal_rows_total{kind}` (kind `tenant_realname` / `invoice_identity`), `superdl_endpoint_auth_denied_total` (service endpoint gateway auth callback denials). Abuse-domain counters: `superdl_user_signup_total`, `superdl_verification_sent_total{channel, purpose}`; tenant egress comes from cAdvisor `container_network_transmit_bytes_total`.

## Rules and invariants

- **Every fault metric has a matching alert rule** (`deploy/cluster/values/kps.yaml`); metrics without a consumer are not kept. The only metric without an alert is `superdl_spot_preempted_total` (its consumer is ops-side PromQL); it increments inside the transaction and is not decremented on rollback, so it is an **upper bound**; reconciliation uses `instance_events` with `reason='preempted'`.
- Security alerts are in the kps rule group `superdl-security` (`superdl.security`): `LoginFailureSpike` (warning, per actor_type, > 50 failures in 5 minutes), `AdminLoginFailureSpike` (critical, > 10 failures in 10 minutes), `AuthzDenialSustained` (warning, 10-minute rate > 0.5/s for 15 minutes), `AdminPrivilegeChanged` (critical, > 0 in 5 minutes), `PiiRevealVolumeHigh` (warning, per kind, > 200 rows in 1 hour), `PiiRevealBurst` (critical, > 500 rows in 5 minutes), `ApiUnauthorizedRateHigh` (warning, 401/403 share > 30 % for 10 minutes), `PaymentConfigWritten` (critical, any write to a payment / crypto config group), `EndpointAuthDenialSustained` (warning, > 1/s for 15 minutes). Runbooks point at Loki queries (`deploy/cluster/runbooks/loki-logging.md`); investigations follow the `request_id` through the whole chain.
- Abuse alerts are in the `superdl-abuse` rule group (`superdl.abuse`): `SignupVelocityHigh` (> 100 sign-ups in 1 hour), `SmsBurst` (> 300 messages per purpose in 10 minutes), `ApiRateLimitedHigh` (application-layer 429 > 5/s for 10 minutes; edge Envoy 429s are not included), `TenantEgressHigh` (a single tenant ns sending > 40 MB/s for 15 minutes). The platform group also has `SshPortPoolLow` / `SshPortPoolExhausted`, `WalletNegativeExposure` (negative-balance exposure > 1000 in the platform currency for 30 minutes), `PaymentReversalReleased` (critical, per event).
- Backup / cluster state / node / billing alerts (platform group `superdl.platform`): `PgBaseBackupStale` (critical, `superdl_pg_basebackup_last_success_timestamp_seconds` older than 8 days or missing for 1 hour), `PgWalSyncStale` (critical, `superdl_pg_wal_sync_last_success_timestamp_seconds` older than 30 minutes or missing for 10 minutes), `K3sStateBackupStale` (critical, `superdl_k3s_state_backup_last_success_timestamp_seconds` older than 13 hours or missing for 30 minutes), `NodeUnenrolledJoined` (critical, `superdl_node_unenrolled` > 0 for 5 minutes: an unenrolled node joined the cluster and has been cordoned, verify the agent token), `SubscriptionUnpaidRunning` (critical, `superdl_subscription_unpaid_running_instances` > 0 for 45 minutes), `ScheduleTimeoutOccupiedBurst` (warning, `superdl_schedule_timeout_occupied_total` increases by > 10 in 1 hour: service instances repeatedly never becoming ready while still billed for occupancy). The certificate group `superdl.certmanager` has `PlatformCertExpiringSoon` (warning, `superdl_cert_not_after_seconds{domain}` within 14 days) / `PlatformCertExpiringCritical` (critical, within 3 days); the three platform domains are renewed by the host acme script, not by cert-manager. The GPU group `superdl.gpu` has `GpuTelemetryMissing` (warning, `DCGM_FI_DEV_GPU_UTIL` or `hami_host_gpu_utilization_ratio` missing for 30 minutes: quota escapes and abuse cannot be detected).
- `superdl_authz_denied_total` counts only in `adminapi/deps.require_roles` (and the PII plaintext gate that shares it); user-side 403s are not counted.
- The request-id runs through the whole chain (contextvars + response header); uncaught exceptions become the unified 500 error body. Exception alerting goes through the log stack (Loki queries in `deploy/cluster/runbooks/loki-logging.md`).
- Logging: structlog + stdlib bridge (ProcessorFormatter); prod = JSON, dev/test = Console; level `SUPERDL_LOG_LEVEL` (default INFO); outbox payloads carry `_request_id`, which the worker restores into the log context when executing.
- **Exception traces carry no local variables**: the prod structured frame renderer explicitly turns off `show_locals`; the dev/test Console renderer pins a plain-text trace (`plain_traceback`) so structlog never switches to rich's locals-rendering trace.
- The worker serves its own `/metrics` port (default 9000, `SUPERDL_WORKER_METRICS_PORT`, same `SUPERDL_METRICS_TOKEN` Bearer). Scrape configuration `deploy/app/k8s/08-monitoring.yaml` = API ServiceMonitor (selected by the Service label `app: superdl-api`, which the Service must carry) + worker PodMonitor (kps needs `podMonitorSelectorNilUsesHelmValues: false`, otherwise only PodMonitors with a `release` label are selected); both live in the `monitoring` namespace with `namespaceSelector` pointing at `superdl`, the Bearer comes from the `token` key of `monitoring/superdl-metrics-token` (value = `SUPERDL_METRICS_TOKEN`, pre-created by ops, existence checked by `deploy/cluster/preflight.sh`): prometheus-operator holds secret read permission only in `monitoring` (`deploy/cluster/monitoring-rbac.yaml`). After go-live verify both scrape pools with Prometheus `up{namespace="superdl"}`.
- The worker logs a warning (`scheduled_tick_slow`) when one round of a scheduled job exceeds 80 % of its period.
- The WorkerDown alert is judged by the heartbeat gauge, not with `absent()`.
- The worker supports graceful SIGTERM shutdown and writes a heartbeat file (the K8s exec probe judges liveness from it); the heartbeat is touched by an independent coroutine.
- Alertmanager critical alerts always go through two channels (platform webhook + external SMTP); an optional third channel Slack / PagerDuty / DingTalk group bot (commented examples in `deploy/cluster/values/kps.yaml`, all disabled by default; DingTalk through a sidecar converter); `oncall_phone` can additionally send on-call SMS directly.
- Daily data cleanup (03:00 in the billing time zone): verification codes, refresh records, completed outbox tasks, audit rows past retention. Retention periods in [limits.md](./limits.md).
- Admin monitoring is drawn in-house, no Grafana iframe: per-card heat cells on the nodes page (util % / VRAM / temperature, red dot when XID > 0) + ECharts curves in the node detail; `grafana_url` is only an external link. When the metric source is down the admin console degrades to a "rented / idle" view.
- Scraping HAMi needs additionalScrapeConfigs in the kps values (scheduler + vGPUmonitor) and an `absent(up{job="hami-scheduler"})` alert.
- Cluster-level query templates are `COMPONENT_QUERIES` in `apps/api/app/modules/metering/prom.py` (DCGM sample freshness / scrape target up ratio / firing alert count), consumed by the node patrol through `cluster_component_metrics()` in `metering/service.py` and merged into the component health snapshot. Prometheus not configured or a failed query returns empty: the matching facts stay empty and no component state changes.
- The light tier uses trimmed values of the same kube-prometheus-stack (grafana off / retention 3d / tighter resources), selected via helmfile environments.
- The backup Job uses an initContainer pg_dump + the official aws-cli image; backup failure and staleness have alerts.
- Metric sources and the user-side metric endpoints are in [metering.md](./metering.md).
