# 账户

Email-primary accounts (phone optional, E.164), verification codes by email or SMS, JWT sessions, SSH keys, identity verification entry point.

## 数据模型

- `users`: `email` (lower-cased, unique when set, `email_verified_at`), `phone` (E.164, unique when set), password_hash (nullable), status (active/frozen/deleted), low_balance_warn_hours, token_version, KYC fields `kyc_status` / `kyc_name` / `kyc_identity_masked` / `kyc_identity_hmac` (keyed digest) / `kyc_provider` / `kyc_ref` / `kyc_verified_at`. At least one handle is set on a live account; both are NULL after deletion.
- `ssh_keys`:user_id、name、public_key、fingerprint(SHA256,唯一)
- `verification_codes`: `channel` (email / sms), `target` (normalized handle), code_hash (keyed digest, domain `vcode|channel|target|purpose`), purpose (register / login / reset_password / bind_handle), expires_at, used_at (voided for any reason), consumed_at (successful check only), attempts
- `used_refresh_tokens`:jti(PK)、expires_at、used_at

## 规则与不变量

- 用户端与管理端 JWT audience 隔离(`SUPERDL_JWT_USER_AUDIENCE` / `SUPERDL_JWT_ADMIN_AUDIENCE`,默认 `superdl:user` / `superdl:admin`;issuer `SUPERDL_JWT_ISSUER` 默认 `superdl`);user token 访问管理端 API 一律 403。
- refresh token 一次性消费:jti 落 `used_refresh_tokens`,重放撤销该用户全部在外 token;同 jti 10s 内重复消费按正常轮换补发,不触发撤销。
- refresh token 只走 HttpOnly Cookie:prod 名 `__Host-superdl_refresh`(Secure + `path=/` + 无 Domain),非 prod `superdl_refresh`。
- `users.token_version` 是撤销闸;冻结用户同步递增。所有 `token_version` 读-改-写(改密/冻结/refresh 重放撤销/logout-all)带行锁(`with_for_update`)。
- 登录限流四层桶,密码路径 bcrypt 前「先计数再判定」(`core/loginguard.login_attempt`,并发下原子):`user-login:{ip}:{handle}` 与 `user-login-acct:{handle}` 成功即清零,`user-login-ip:{ip}` 成功退还本次计数,`user-login-acct-daily:{handle}` 只在失败后计数、不做准入(`handle` = `core/handles.ratelimit_key`, hashed beyond 48 chars);验证码路径只在失败后计数;注册、找回密码、实名核验与发码各有桶。计数落 PG(见 [security.md](./security.md)),限额见 [limits.md](./limits.md)。
- 密码规则只有一处 `core/security.PasswordStr`(≥12 字符、UTF-8 ≤72 字节,bcrypt 上限),用户端与管理端请求体共用,不合格 422。
- 验证码失败计次 `attempts` 达上限即作废(置 `used_at`,`consumed_at` 仍空)。Send gate order (`account/verification.py`): per-target precheck bucket → CAPTCHA → per-IP bucket → per-target backoff (advisory lock on `kind:value`) → per-target daily cap → platform budget of the channel (`core/sms.ensure_sms_platform_quota` / `core/email.ensure_email_platform_quota`). 退避:同 target 最新一条距今不足 `SUPERDL_SMS_SEND_INTERVAL_SECONDS` 即拒;连续 N 条 `consumed_at` 为空(含烧码作废、过期)时间隔 × 2^(N-1)(指数封顶 3),报 `CODE_TOO_FREQUENT`. Codes are `CODE_INVALID` / `CODE_TOO_FREQUENT` / `CODE_SEND_FAILED` regardless of channel.
- A delivery failure (SMS or email) voids the stored code and returns 502.
- Handles: `core/handles.py` normalizes (email lower-cased; phone E.164 with separators stripped) and masks (`mask_handle`: `a***@domain`, `+86****1111`); bare national numbers are not accepted anywhere. Sign-up needs an email; a phone is bound at sign-up or later via `/me/handles/*`, and the compliance profile (`core/compliance.py`) decides whether it is required and which dial codes are allowed. Accounts that predate email handles keep logging in by phone; the console shows an add-your-email banner until they bind one.
- 公钥须为 ssh-ed25519 / ssh-rsa / ecdsa-*;唯一性按 (user_id, fingerprint),重复报 `SSH_KEY_DUPLICATE`,非法报 `SSH_KEY_INVALID`;删除为硬删除。
- 身份证号只存脱敏值 + 带密钥摘要(`crypto.hash_kyc_identity`, digest domain unchanged so pre-rename values still match,原文不落库);a pass records `kyc_provider` / `kyc_ref` / `kyc_verified_at`;同摘要的非注销账号数达 `real_name_max_accounts_per_identity`(默认 3)即 409 `account.realNameIdentityLimit`。`real_name_enabled` 控制能否提交实名,`real_name_required_for_recharge` 控制充值/开通实例是否强制已实名 — the gate is inert when the compliance profile offers no KYC form (`current_profile().kyc_form is None`). 不变量:后者开启要求前者开启。
- 密码登录:四层桶先计数 → 查用户 → **先提交只读事务还连接** → bcrypt(专属 4 线程池 `core/security._BCRYPT_EXECUTOR`,在途上限 64,超出直接 429 不排队)→ 成功退还 / 清零;注册成功计 `superdl_user_signup_total`,发码成功计 `superdl_verification_sent_total{channel, purpose}`。
- SSH 公钥:每用户 50 把、添加 20 次/小时(`MAX_SSH_KEYS_PER_USER`);创建实例按 id 集合下推 SQL 取键(`ssh_keys_by_ids`)。
- 注册必勾条款,同事务按当前 published 版落 terms/privacy 各一条同意存证。
- 注销执行为匿名化:both handles and `email_verified_at` become NULL (the handle is free for a new account), KYC name / masked identity / provider / ref / verified_at cleared, `kyc_identity_hmac` kept for the per-identity cap, 全撤登录态;`balance_ledger` 与账单按法定义务保留。执行请求体必带操作原因 `note`,回写 `account_deletion_requests.note`(与驳回理由同列)。
- 所有写操作过审计中间件(actor/ip/result)。
