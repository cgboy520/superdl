# User console

`apps/web`: public layer + console. Visual spec in `docs/ui-ux-spec.md`.

The main navigation's source of truth is `apps/web/src/components/layout/consoleNav.tsx` (`CONSOLE_NAV_GROUPS`: resources / purchasing & billing / support; shared by the sidebar, the narrow-screen drawer and the command palette); `/notifications` and `/settings` are not in the main navigation and are reached through the top-bar bell and the user menu. Every console page owns its `PageContainer` (the shell `_console.tsx` only provides the top bar / sidebar / `<main>`).

## Rules and invariants

- All server state goes through TanStack Query and every request uses the generated fetchers (hooks are built in `api/queries.ts` / `api/mutations.ts`; query keys only in `api/keys.ts`, invalidation and definitions reference the same factory); hand-written fetch is forbidden; copy and status maps come from `packages/ui`; antd 6 native components are wrapped in-house.
- Non-route files under `src/routes/` start with `-` (tanstack router's routeFileIgnorePrefix); antd 6 deprecated props (e.g. `maskClosable` → `mask={{closable}}`) are migrated as soon as the deprecation warning appears.
- 401 is refreshed silently and replayed by the mutator (single-flight); only a failed refresh redirects to login with a return path.
- A failed query must never masquerade as data: the table error state and the page-level banner from `packages/ui/src/components/QueryState.tsx` are used everywhere, amounts that are not ready render `EmptyValue`, a failed detail page shows an error banner + retry.
- Balance and amount comparisons use `compareAmounts` (BigInt), the daily disk estimate uses `ui.diskDailyEstimate`; the frontend does no float arithmetic.
- Creation failure loop: a failed row shows the reason and the not-charged note inline and offers recreation; `NO_CAPACITY` stays in the checkout bar's `notice` slot and offers "pick another spec"; a fresh Idempotency-Key is generated before resubmitting. When the disk was created but the instance failed, the user is told the data disk is already billed and can be managed.
- Top-up polling stops at a terminal state (paid/closed/failed); channel tiles list only the enabled channels returned by `/site-config.payment_channels` (labels from `paymentChannelMap`, unknown channels show their raw name); `presentation=qr` renders a QR code, `redirect` navigates to `payment_url`, and when the provider returns to `/billing?recharge=<order_no>[&cancelled=1]` the modal reopens automatically and resumes polling (after the `cancelled` notice the order can still be paid).
- When the metric source is down, that column / area degrades to "monitoring temporarily unavailable"; the rest of the page works as usual.
- Rows with zero stock are greyed, not hidden; conditional actions always use `GatedButton` (visible, focusable, with a reason). **Whether a placeholder stays has a criterion** (see [../ui-ux-spec.md](../ui-ux-spec.md) §1 rule 4). The period chip is greyed only when the selected spec has `period_enabled=false`, the spot chip only with `spot_enabled=false`, phrased as "not supported by this spec".
- The billing mode on the market page and the create page is a `ChipRow` (`role=group`, group name "Billing mode"); e2e depends on that accessible name.
- **Discounts, expiry warning days and the preemption grace window always come from `GET /api/v1/policies`, never hard-coded**: the discount and the "N seconds' notice" in the spot consent come from `spot_discount_pct` / `spot_grace_seconds`.
- **The "convert to on-demand" confirmation must state two things**: the instance is no longer reclaimable after conversion, and **the current clock hour is settled entirely at the on-demand price** (extra charge only, no refund, see [billing.md](./billing.md)). It carries no `Idempotency-Key`.
- "Convert to subscription" is available for on-demand instances only and is a one-off prepaid payment; the confirmation says the on-demand charges are settled first and there is no refund after conversion.
- **Subscription amounts follow the server quote.** Order and renewal responses carry the full quote triple (list price / discount / payable), which the frontend renders line by line without multiplying; before submitting, the market and create pages only compute a display value from the `/policies` discount and state that the final quote prevails. Renewal and conversion requests both carry an `Idempotency-Key` (one generated per modal opening).
- A preempted spot instance goes `stopping → stopped`; **the event timeline's reason map must cover `preempted`**.
- Expiry information is inlined in `InstanceOut.subscription` (batch back-filled once for the list); the list page **must not** call the API per row; the status count bar counts loaded rows and shows no number until loading finishes.
- A service's `unready` **is not rendered as a fault** (warning badge + explanatory tooltip); the endpoint card shows it faithfully and points to the logs (see [services.md](./services.md)). The service detail hangs one `useService` poll only; monitoring / bills / logs use the service-level hooks (`useService*` in `api/queries.ts`), invalidation domain `SERVICE_INVALIDATES`.
- Months and other dates are computed in the local time zone; `/instances/:uuid` survives a direct refresh.
- Jupyter `window.open` carries `noopener,noreferrer`.
- On-demand echarts registration is concentrated in the `EChart` component of `packages/ui`, themed via `useChartTheme()`; design tokens and global styles (`packages/ui/src/base.css` + `apps/web/src/styles.css`) are unified with no hard-coded colours; JS-side semantic colours only through `useThemeColors()`.
- The public layer's monospace font is self-hosted in web's public directory (`@font-face` in `apps/web/src/styles.css`), CSP `font-src 'self'` already allows it; the `index.html` inline script is not changed.
