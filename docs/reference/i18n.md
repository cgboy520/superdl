# Copy and internationalisation

Language set en-US (baseline) + zh-CN, complete on both consoles. Copy rules in `docs/copy-style-guide.md`.

## Contract

Backend error response body `{code, message, message_key, params, detail, request_id}`; `AppError(code, message=None, *, key=None, params=None, ...)`.
The error body is assembled by the exception handler and is not part of the openapi schema.

## Rules and invariants

- Toolchain react-i18next + i18next + i18next-cli (key extraction / TS type generation / hard-coded-string lint / locale sync); plurals use the `_one/_other` suffixes, no ICU library.
- The initialisation shell is `packages/ui/src/i18n.ts::initAppI18n` (LanguageDetector: localStorage `superdl.lang` → navigator; fallbackLng en-US); each console has its own `src/i18n.ts` that registers only its own namespaces. `packages/ui/src/hooks/useAppLocale.ts::useAppLocale` is the single outlet that keeps antd ConfigProvider locale, dayjs locale, html lang and document.title in step.
- Namespaces: `web` / `admin` / `shared` (`packages/ui/locales/`, status tables and format units, hand-maintained + guarded by unit tests) / `errors` (en-US is generated from the backend MESSAGES by `apps/api/scripts/export_error_messages.py` and locked by a CI no-diff check; zh-CN is hand-maintained, `tests/test_errors_i18n.py` locks key set and placeholder parity). Resources are statically imported and fully bundled.
- Backend error copy has one source of truth, `core/messages.py` (English); the frontend resolves copy by `message_key`, never by looking up ErrorCode. `packages/api-client/src/mutator.ts` sends `Accept-Language` (the current UI language) with every request; server-rendered verification SMS / emails pick their language from it.
- `render_message` falls back to the key and warns on a missing key, never 500; 422/500 fall back to `common.validation` / `common.internal`; the response `message` keeps the English fallback, tests assert the code, not the copy.
- The frontend resolves errors through `apiErrorText(t, err, fallback)` in `packages/ui/src/apiError.ts` against the `errors` ns, falling back to the server's English `message` on a missing key; the cast for dynamic server keys is concentrated in `useApiErrorText()` from `@superdl/ui`, and web's single error outlet is `apps/web/src/api/mutations.ts`.
- JSON is the only value carrier, code never writes defaultValue; array copy uses one literal key per item, never `returnObjects`.
- `packages/ui` has zero runtime dependencies: status tables export only labelKey (with the embedded `shared:` prefix, `as const satisfies`), and `t` is held explicitly by the calling component.
- format functions take trailing locale/t parameters; en uses abbreviated units to avoid plurals, real plural points go through `_one/_other`; the money-number pipeline is pure string arithmetic and never passes through `Number`.
- Money formatting goes through `Intl.NumberFormat` (`packages/ui/src/format.ts`): the currency code comes from `CurrencyProvider` (web reads `/site-config.currency`, admin reads `GET /api/admin/v1/deployment` (every console role); until known only the number is shown), the symbol is chosen by Intl per locale (zh-CN/CNY `¥`, en-US/CNY `CN¥`, en-US/USD `$`), fraction digits are truncated to the currency's minor unit (no arithmetic); locale strings no longer embed currency symbols, amounts are always formatted first and passed as `{{amount}}`.
- `formatDateTime` outputs `YYYY-MM-DD HH:mm (UTC±h)` (the browser's local time zone).
- Constraint copy follows the backend message_key; the frontend must not reuse one key for both a tooltip and an error dialog.
- Gates: one `i18next.config.ts` per app (extract; types artefacts are committed and CI checks for no diff; lint for hard-coded strings and interpolation mismatches); each app's `src/locales/locales.test.ts` locks equal zh/en key sets, non-empty values and consistent `{{}}` placeholders (the parity assertions come from the `@superdl/ui/localeParity` subpath and stay out of the runtime barrel); `packages/ui` unit tests lock status-table labelKey/hintKey parity with the errors key set; CJK leftovers are guarded by `scripts/check-cjk.sh` (default mode scans both consoles' source; `--scope repo` scans the whole repository's source and docs, with permanent exemptions for locales / generated artefacts / shipped migrations / legal presets / e2e, the inline `cjk-ok` marker for regulatory terms, and `REPO_CJK_ALLOW` as the shrink-only list of prefixes still awaiting translation, run by the CI `docs` job; web additionally runs `i18next-cli lint`); banned words are caught by `scripts/check-copy-banned.sh`; both run once each via `copy-check` in the root `package.json` at the end of `pnpm i18n`; hand-written URLs are caught by eslint (`no-restricted-globals` bans bare `fetch`, `no-restricted-imports` bans `customFetch` / direct mutator use).
- e2e pins `use.locale: "zh-CN"`; selectors prefer role + accessible name (the Chinese copy is the contract), `data-testid` is used only for elements without a stable role / copy, with the list centralised in the packages/ui testIds module.
- Field labels, policy parameter names and risk copy of the admin platform configuration live in the `admin` ns; only regulatory registration names without an official English name keep the Chinese term in en-US, allow-listed per key through `allowCjkInEn` in `locales.test.ts`.
- Verification-code SMS and email bodies are rendered server-side from `app/core/verification/templates.py` (en-US, zh-CN; callers pass the negotiated locale, default en-US). In-app notifications, admin alerts and ledger remarks are rendered from `app/core/servercopy.py` (`copy(key, **params)`, en-US + zh-CN, locale = the compliance profile's default locale, never the request language) and stored rendered, so they do not switch with the UI language; CSV exports take `lang` (zh-CN / en-US) and default to the same profile locale; legal pages are per-locale whole-page resources whose default language and fallback chain are decided by the compliance profile (see [legal.md](./legal.md)).
