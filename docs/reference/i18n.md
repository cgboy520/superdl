# 文案与国际化

语言集 en-US(基准)+ zh-CN,两端全量。文案规范见 `docs/copy-style-guide.md`。

## 契约

后端错误响应体 `{code, message, message_key, params, detail}`;`AppError(code, message=None, *, key=None, params=None, ...)`。
错误体由 exception handler 拼装、不进 openapi schema。

## 规则与不变量

- 工具链 react-i18next + i18next + i18next-cli(key 提取 / TS 类型生成 / 硬编码 lint / locale 同步);复数用 `_one/_other` 后缀,不引 ICU 库。
- 初始化壳在 `packages/ui/src/i18n.ts::initAppI18n`(LanguageDetector:localStorage `superdl.lang` → navigator;fallbackLng en-US);两端各有 `src/i18n.ts`,只注册本端 ns 语言包。`packages/ui/src/hooks/useAppLocale.ts::useAppLocale` 是 antd ConfigProvider locale、dayjs locale、html lang、document.title 四联动的唯一出口。
- namespace:`web` / `admin` / `shared`(`packages/ui/locales/`,状态表与 format 量词,手维护 + 单测守护)/ `errors`(en-US 由后端 MESSAGES 经 `apps/api/scripts/export_error_messages.py` 生成并 CI no-diff 锁;zh-CN 手维护,`tests/test_errors_i18n.py` 锁键集与占位符齐平)。资源静态 import 全量打包。
- 后端错误文案以 `core/messages.py`(English)为单一事实源;前端按 `message_key` 取文案,禁止按 ErrorCode 查表。`packages/api-client/src/mutator.ts` 随每个请求发送 `Accept-Language`(当前 UI 语言),服务端渲染的验证码短信 / 邮件据此选语言。
- `render_message` 缺键时回落 key 并告警,不得 500;422/500 兜底 `common.validation` / `common.internal`;响应体 `message` 保留 English 兜底,测试断 code 不断文案。
- 前端经 `packages/ui/src/apiError.ts` 的 `apiErrorText(t, err, fallback)` 查 `errors` ns,缺键回落服务端 English `message`;动态 server key 的 cast 收敛在 `@superdl/ui` 的 `useApiErrorText()`,web 统一错误出口 `apps/web/src/api/mutations.ts`。
- JSON 是唯一值载体,代码不写 defaultValue;数组文案逐条字面量键,不用 `returnObjects`。
- `packages/ui` 零运行时依赖:状态表只导出 labelKey(内嵌 `shared:` 前缀,`as const satisfies`),`t` 由调用组件显式持有。
- format 函数带 locale/t 尾参;en 用缩写单位规避复数,真复数点走 `_one/_other`;金额数字管线纯字符串运算,不过 `Number`。
- 金额格式化走 `Intl.NumberFormat`(`packages/ui/src/format.ts`):货币码来自 `CurrencyProvider`(web 取 `/site-config.currency`,admin 取 platform-config `deployment.currency`;未知前只显示数字),符号由 Intl 按 locale 给出(zh-CN/CNY `¥`、en-US/CNY `CN¥`、en-US/USD `$`),小数位按币种最小单位截断(不做算术);locale 文案不再内嵌货币符号,金额一律先格式化再作 `{{amount}}` 传入。
- `formatDateTime` 输出 `YYYY-MM-DD HH:mm (UTC±h)`(浏览器本地时区)。
- 约束类文案以后端 message_key 为准,前端禁止 tooltip 与错误弹窗复用同一键。
- 闸门:每 app 一份 `i18next.config.ts`(extract、types 产物入库且 CI 校验无 diff、lint 硬编码与插值 mismatch);每 app `src/locales/locales.test.ts` 锁 zh/en 键集相等、值非空、`{{}}` 占位符一致(parity 断言经 `@superdl/ui/localeParity` 子路径,不进运行时 barrel);`packages/ui` 单测锁状态表 labelKey/hintKey 与 errors 键集 parity;CJK 残留由 `scripts/check-cjk.sh` 守护(web 另跑 `i18next-cli lint`),禁词由 `scripts/check-copy-banned.sh` 拦截,两者经根 `package.json` 的 `copy-check` 在 `pnpm i18n` 末尾各跑一次;手写 URL 由 eslint 拦(`no-restricted-globals` 禁裸 `fetch`,`no-restricted-imports` 禁 `customFetch`/直连 mutator)。
- admin `platform.tsx` 等中国渠道运营域文案不译,CJK 闸门豁免。
- e2e 钉 `use.locale: "zh-CN"`;选择器优先 role + 可访问名(中文文案即契约),`data-testid` 只用于无稳定 role / 文案的元素,清单集中在 packages/ui 的 testIds 模块。
- 管理端平台配置的字段标签、策略参数名与风险复述进 `admin` ns;只有中国渠道运营域的专有名词按 `i18n-exempt` 不译。
- Verification-code SMS and email bodies are rendered server-side from `app/core/verification/templates.py` (en-US, zh-CN; callers pass the negotiated locale, default en-US);站内信存已渲染文案,不随语言切换;legal 页 per-locale 整页资源,默认语言与回落链由 compliance profile 决定(见 [legal.md](./legal.md))。
