# Organizations

Groups individual accounts under shared administration. A user belongs to at most one organization; owners and admins see members' spending at a glance. Funds, bills, invoices, refunds, quotas and resources stay with each member's own account; an organization never pays for, stops or reads into a member's resources. The decision and its constraints are in [decisions.md](../decisions.md).

## Data model

- `organizations`: `uuid` unique, `name` (2–40 letters of any script, digits, spaces and `. & ( ) + - _`, starting with a letter or digit; no links or markup), `status` (CHECK ∈ {active, dissolved}), `created_by`, `created_at`, `dissolved_at?`, `idempotency_key?` + `request_fingerprint?` (UNIQUE `(created_by, idempotency_key)`). A dissolved row is kept and has no members or pending invitations.
- `org_members`: `org_id` (FK), `user_id` (UNIQUE: one organization per user), `role` (CHECK ∈ {owner, admin, member}; partial unique `(org_id) WHERE role = 'owner'`: exactly one owner), `remark?` (≤ 64, set by owners and admins), `invited_by?`, `consent_version` (the disclosure version the member accepted), `joined_at`
- `org_invitations`: `uuid` unique, `org_id` (FK), `email` (normalised), `role` (CHECK ∈ {admin, member}), `remark?` (copied to the membership on acceptance), `status` (CHECK ∈ {pending, accepted, declined, revoked, expired}; partial unique `(org_id, email) WHERE status = 'pending'`), `invited_by`, `created_at`, `expires_at` (7 days), `responded_at?`. A pending row past `expires_at` reads as `expired` and is written back when the organization invites again.

## Contract

Roles: O = owner, A = admin, M = member, N = a user outside any organization.

| Endpoint                                               | Role / auth              | Notes                                                                                                                                                                                            |
| ------------------------------------------------------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/v1/org`                                      | user                     | The caller's organization, role, `member_id`, member count and admins (masked emails); `org` null outside one; `received_invitations` counts pending invitations to the caller                   |
| `GET /api/v1/org/disclosure`                           | user                     | `version` and the items owners and admins can see (`identity`, `available_balance`, `month_to_date`, `burn_rate`, `instances`, `routed_access`)                                                  |
| `POST /api/v1/org`                                     | N                        | 201; Idempotency-Key (replay 200 + `X-Idempotent-Replay`); identity verification when required (`orgs.realNameRequired`); 3/day per user; a member of an organization → 409 `orgs.alreadyMember` |
| `PATCH /api/v1/org`                                    | O                        | Rename                                                                                                                                                                                           |
| `POST /api/v1/org/transfer`                            | O                        | `{member_id}`: the target becomes owner, the caller admin                                                                                                                                        |
| `POST /api/v1/org/dissolve`                            | O                        | `{confirm_name}` must equal the name (`orgs.confirmNameMismatch`); ends every membership and pending invitation, notifies the other members                                                      |
| `POST /api/v1/org/leave`                               | A, M                     | The owner gets 409 `orgs.ownerCannotLeave`                                                                                                                                                       |
| `GET /api/v1/org/members`                              | O, A                     | `member_id`, role, label (remark or masked email), masked email, remark, account status, `joined_at`                                                                                             |
| `PATCH /api/v1/org/members/{member_id}`                | O (role), O / A (remark) | Role ∈ {admin, member}; the owner role moves only by transfer (`orgs.ownerRoleViaTransfer`); an empty remark clears it                                                                           |
| `DELETE /api/v1/org/members/{member_id}`               | O, A                     | 204; the owner removes anyone else, an admin removes members only; never the owner, never oneself (`orgs.useLeave`); the member is notified                                                      |
| `GET /api/v1/org/invitations`                          | O, A                     | Sent invitations, newest 200, with the email as typed                                                                                                                                            |
| `POST /api/v1/org/invitations`                         | O, A                     | 201 `{email, role, remark?}`; admins invite members only; a pending invitation for the same email is returned unchanged; 30/h per user                                                           |
| `DELETE /api/v1/org/invitations/{uuid}`                | O, A                     | 204; pending only (`orgs.invitationNotPending`)                                                                                                                                                  |
| `GET /api/v1/org/invitations/received`                 | user                     | Pending, unexpired invitations to the caller's verified email; `blocked = member_of_org` while the caller belongs to an organization                                                             |
| `POST /api/v1/org/invitations/received/{uuid}/accept`  | user                     | `{consent_version}` must be the current disclosure (`orgs.consentOutdated`); joins with the invited role; member cap → 409 `orgs.memberQuota`                                                    |
| `POST /api/v1/org/invitations/received/{uuid}/decline` | user                     | 204                                                                                                                                                                                              |
| `GET /api/v1/org/finance`                              | O, A                     | Every read is audited (`org-finance:<user id>`); fields below                                                                                                                                    |
| `GET /api/admin/v1/orgs`                               | ops / finance / readonly | Cursor paged, newest first; `q` = organization uuid, a member's user id or a name fragment (audited); owner user id and masked email, member and pending-invitation counts                       |
| `GET /api/admin/v1/orgs/{uuid}`                        | ops / finance / readonly | Members (user id, role, masked email, account status) and invitations (masked email), audited                                                                                                    |
| `POST /api/admin/v1/orgs/{uuid}/dissolve`              | ops                      | Reason required (audited); same effect as the owner's dissolve                                                                                                                                   |
| `POST /api/admin/v1/orgs/{uuid}/members/remove`        | ops                      | `{user_id, reason}`; never the owner                                                                                                                                                             |
| `POST /api/admin/v1/orgs/{uuid}/transfer`              | admin                    | `{user_id, reason}`: the member becomes owner, the previous owner admin                                                                                                                          |

Every write passes through the audit middleware; the organization role is read from `org_members` on each request, never carried in the JWT.

`GET /api/v1/org/finance` returns `currency`, `billing_timezone`, `period` (YYYY-MM in the billing zone), `period_start`, `generated_at`, per member `member_id`, `role`, `label`, `available_balance` (balance − frozen), `month_to_date` (hourly and daily-disk bills attributed to `[window_start, period end)`, `window_start` = max(billing month start, `joined_at`)), `burn_per_hour` (running instances outside subscriptions, 4 decimals), `running_instances` (subscriptions included), `est_hours_left` (available ÷ burn, 1 decimal; null without burn, 0 at or below zero; excludes the current, not yet settled hour) and `totals`. Amounts are decimal strings.

## Rules and invariants

- **What owners and admins see is exactly the disclosure**: masked email, remark, role, join time and account status; available balance, month-to-date bills since joining, hourly burn and hours left. Never the phone number, identity-verification data, SSH keys, sign-in history, ledger entries, orders, invoices, refunds, instance access data (SSH endpoint, Jupyter token, ports, node, addresses) or logs. Members see the organization's name, their role and the admins' masked emails.
- **No organization action reaches into a member's account**: no top-up, transfer, stop, start or release.
- **Invitations never reveal accounts**: the invite request path never reads the user table; the answer and the sent list are identical whether or not an account exists for the email. The in-app notice is the outbox task `orgs.invite_notify` (worker `core` component), which resolves the email to an active account with that verified email; no email is sent. Only a session whose verified email matches can see, accept or decline the invitation.
- **Consent is recorded**: accepting requires the current `consent_version`; the membership stores it. Changing the disclosure items bumps `CONSENT_VERSION` in `apps/api/app/modules/orgs/service.py`.
- **Lock order** is organization row → member / invitation rows for every organization-scoped write (`require_org_role(..., lock=True)`, `lock_org`); accepting locks the organization before the invitation.
- **Membership listeners**: removing members (leave, removal, admin removal, account deletion) runs the listeners registered through `register_members_removed_listener` after the rows are deleted; dissolving runs `register_org_dissolved_listener` listeners. Both run before commit in the same transaction and never commit; an exception rolls the change back. Other modules register them from `app/wiring.py`; `orgs` imports no module that registers one.
- **Exactly one owner**: transfers demote, flush, then promote (the partial unique index is not deferrable). The owner cannot leave or be removed; transfer or dissolve first.
- **Account deletion** ([account.md](./account.md)): owning an organization with other members refuses the request and auto-rejects the approval (`account.deletionOrgOwner`); approval removes the membership in the same transaction, and a sole owner's organization dissolves.
- **Notifications** (type `org`, rendered in the deployment's locale): invitation, removal, dissolution, ownership received. Leaving notifies no one.
- Limits: `SUPERDL_ORG_MAX_MEMBERS` (default 50) members per organization, `SUPERDL_ORG_MAX_PENDING_INVITATIONS` (default 50) pending invitations; see [limits.md](./limits.md).
