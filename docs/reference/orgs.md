# Tenants

A tenant (module `orgs`, API under `/org`) groups accounts under shared administration. A user belongs to at most one tenant. Owners and admins see members' spending at a glance, run the tenant's private-network gateways ([netgw.md](./netgw.md)), create accounts for their people (username sign-in, no identity verification), move balance to and from members, and mount the tenant's own Ceph directories into every member's instances. Bills, invoices, refunds, quotas and resources stay with each member's own account; a tenant never stops or reads into a member's resources. The decisions and their constraints are in [decisions.md](../decisions.md).

## Data model

- `organizations`: `uuid` unique, `code` unique (2–20 lowercase letters, digits or dashes, starting with a letter: the username prefix of the accounts the tenant creates), `name` (2–40 letters of any script, digits, spaces and `. & ( ) + - _`, starting with a letter or digit; no links or markup), `status` (CHECK ∈ {active, dissolved}), `created_by`, `created_at`, `dissolved_at?`, `idempotency_key?` + `request_fingerprint?` (UNIQUE `(created_by, idempotency_key)`). A dissolved row is kept and has no members or pending invitations.
- `org_members`: `org_id` (FK), `user_id` (UNIQUE: one tenant per user), `role` (CHECK ∈ {owner, admin, member}; partial unique `(org_id) WHERE role = 'owner'`: exactly one owner), `remark?` (≤ 64, set by owners and admins), `invited_by?`, `consent_version` (the disclosure version the member accepted), `joined_at`
- `users.managed_org_id` / `username` (`<code>.<name>`, unique) / `login_disabled` / `password_change_required`: accounts a tenant created ([account.md](./account.md))
- `org_transfers`: `uuid`, `org_id`, `kind` (allocate / reclaim), `from_user_id`, `to_user_id`, `amount` (> 0, 2 decimals), `created_by`, `idempotency_key?` + `request_fingerprint?` (UNIQUE `(created_by, idempotency_key)`), `created_at`; the two ledger rows carry `ref_type = org_transfer`
- `org_mounts`: `uuid`, `org_id`, `name` (unique per tenant, `[a-z0-9][a-z0-9._-]{0,39}`, mounted at `/mnt/org/<name>`), `ceph_path`, `ceph_user` (cephx id without `client.`), `key_encrypted` (AES-GCM with the configuration key), `read_only` (default true), `enabled`, `revision` (bumped by every change that alters the mount), `status` (checking / ready / failed), `last_error`, `checked_at`, `created_by`
- `org_invitations`: `uuid` unique, `org_id` (FK), `email` (normalised), `role` (CHECK ∈ {admin, member}), `remark?` (copied to the membership on acceptance), `status` (CHECK ∈ {pending, accepted, declined, revoked, expired}; partial unique `(org_id, email) WHERE status = 'pending'`), `invited_by`, `created_at`, `expires_at` (7 days), `responded_at?`. A pending row past `expires_at` reads as `expired` and is written back when the tenant invites again.

## Contract

Roles: O = owner, A = admin, M = member, N = a user outside any tenant.

¹ Accounts the tenant created only (`orgs.notManaged`): the owner acts on any of them, an admin on those with the member role; nobody on their own account (`orgs.managedSelf`).

Every write passes through the audit middleware; the tenant role is read from `org_members` on each request, never carried in the JWT.

`GET /api/v1/org/finance` returns `currency`, `billing_timezone`, `period` (YYYY-MM in the billing zone), `period_start`, `generated_at`, per member `member_id`, `role`, `label`, `available_balance` (balance − frozen), `month_to_date` (hourly and daily-disk bills attributed to `[window_start, period end)`, `window_start` = max(billing month start, `joined_at`)), `burn_per_hour` (running instances outside subscriptions, 4 decimals), `running_instances` (subscriptions included), `est_hours_left` (available ÷ burn, 1 decimal; null without burn, 0 at or below zero; excludes the current, not yet settled hour) and `totals`. Amounts are decimal strings.

## Rules and invariants

- **Accounts a tenant creates** sign in with `<code>.<name>` and a password only (no verification codes: `account.usernameNoCode`), must choose their own password at first sign-in, need no identity verification anywhere, cannot leave the tenant (`orgs.managedCannotLeave`), cannot be removed (`orgs.managedUseDelete`, delete the account instead) and cannot become owner. A tenant with created accounts cannot be dissolved (`orgs.dissolveHasManagedUsers`), by its owner or by platform admins.
- **Balance moves** lock both wallets in id order and write a `transfer_out` and a `transfer_in` ledger row (`ref_type = org_transfer`, remarks in the deployment's locale); the member is notified. Moved money can only be spent: neither side of a move counts toward refundable capacity and invoices follow paid orders, so the recipient cannot refund or invoice it, while the payer can again once it is reclaimed.

- **Storage mounts**: each mount is a directory on the platform's Ceph cluster reached with the tenant's own cephx key; ids the platform issues (`<ceph_auth_prefix>u<id>-sys-…` / `-disk-…`) and the admin id are refused. The `orgs.mount_check` task (tenant-mgr) mounts the path with libcephfs in a separate process (`app/core/ceph/pathcheck.py`) and records ready / failed; only enabled, ready mounts reach instances. Every member's instances mount them at `/mnt/org/<name>` (read-only unless configured otherwise) from their next start, through per-namespace static PV + PVC + Secret objects named `om-<uuid>-r<revision>`; a change bumps the revision, so new Pods take the new objects while running ones keep theirs, and `orgs.mount_sweep` removes revisions no Pod uses any more. Removing a member or dissolving the tenant sweeps the objects of the namespaces concerned. Members are notified when a mount is added. Limit `SUPERDL_ORG_MAX_MOUNTS` (default 8).
- **What owners and admins see is exactly the disclosure**: masked email, remark, role, join time and account status; available balance, month-to-date bills since joining, hourly burn and hours left; the member's unreleased dev instances (name, state, attach eligibility) for tenant gateways. Never the phone number, identity-verification data, SSH keys, sign-in history, ledger entries, orders, invoices, refunds, instance access data (SSH endpoint, Jupyter token, ports, node, addresses) or logs. Members see the tenant's name, their role and the admins' masked emails.
- **No tenant action reaches into a member's account**: no top-up, transfer, stop, start or release; attaching a member's instance to a tenant gateway is the only tenant action on a member's resource, the member is notified and can always detach it.
- **Invitations never reveal accounts**: the invite request path never reads the user table; the answer and the sent list are identical whether or not an account exists for the email. The in-app notice is the outbox task `orgs.invite_notify` (worker `core` component), which resolves the email to an active account with that verified email; no email is sent. Only a session whose verified email matches can see, accept or decline the invitation.
- **Consent is recorded**: accepting requires the current `consent_version`; the membership stores it. Changing the disclosure items bumps `CONSENT_VERSION` in `apps/api/app/modules/orgs/service.py`.
- **Lock order** is tenant row → member / invitation rows for every tenant-scoped write (`require_org_role(..., lock=True)`, `lock_org`); accepting locks the tenant before the invitation. Tenant gateway writes take the same lock first.
- **Membership listeners**: removing members (leave, removal, admin removal, account deletion) runs the listeners registered through `register_members_removed_listener` after the rows are deleted; dissolving runs `register_org_dissolved_listener` listeners. Both run before commit in the same transaction and never commit; an exception rolls the change back. Netgw registers both from `app/wiring.py` (removed members' attachments leave the tenant's gateways; dissolving deletes them); `orgs` never imports `netgw`.
- **Exactly one owner**: transfers demote, flush, then promote (the partial unique index is not deferrable). The owner cannot leave or be removed; transfer or dissolve first.
- **Account deletion** ([account.md](./account.md)): owning a tenant with other members refuses the request and auto-rejects the approval (`account.deletionOrgOwner`); approval removes the membership in the same transaction, and a sole owner's tenant dissolves. The role is re-read under the tenant lock, so a transfer that lands meanwhile refuses the approval instead of dissolving the tenant.
- **Notifications** (type `org`, rendered in the deployment's locale): invitation, removal, dissolution, ownership received. Leaving notifies no one.
- Limits: `SUPERDL_ORG_MAX_MEMBERS` (default 50) members per tenant, `SUPERDL_ORG_MAX_PENDING_INVITATIONS` (default 50) pending invitations; see [limits.md](./limits.md).
